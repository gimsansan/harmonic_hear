# 하모니 튠 (HarmoniTune) — 통합 구현 명세서

> 본 문서는 4개의 참조 문서(① 초기 앱 구현 명세서 · ② 검증 앱 구현 사양서 · ③ 음향 엔진·자극 생성 구조 설계서 · ④ 웹 오디오 음고 구현 인계문)를 하나로 통합·정정한 마스터 구현 명세서입니다. 검증 과정에서 섞이거나 중복·역전된 내용을 정리하고, 상충하던 아키텍처 결정을 일관되게 통일했습니다.

## 0. 문서 정리 노트 (통합 시 정정·통일한 항목)

원본 4개 문서 사이의 주요 불일치를 다음과 같이 처리했습니다.

- **'사람 목소리' 자극 생성 방식의 상충 통일.** 초기 문서는 포먼트 합성(DSP)으로 구현했으나, 이후 음향 엔진 분석에서 **키존 다중 샘플링(실제 녹음)**을 최종 선정했습니다. 본 문서는 키존을 '사람 목소리' 자연음 경로의 **최종안**으로 두고, 포먼트 합성은 **대안 / 현행 코드 구현체**로 위치를 명확히 분리했습니다. (§4)
- **'100% 보존/유지' 과잉 표현 정정.** 리샘플링 기반 피치 시프트의 "음색 100% 유지" 주장은 거짓으로 판정되어 삭제. 스템 재생의 "100% 보존"도 분리 모델의 본질적 한계를 반영해 완화했습니다. (§3, §5.4, §9)
- **detune 오해 정정.** detune은 포먼트 보존 기능이 아니며, playbackRate와 동일한 리샘플링 엔진을 공유합니다. (§5.1)
- **재생 길이 수치의 방향 비대칭 명시.** 단일 수치 "+5.95%"는 피치 다운 방향 최대값이며, 피치 업은 −5.61%로 다릅니다. (§5.2)
- **용어 표기 통일.** '±1반음'은 최근접 샘플 기준 최대 시프트 ±100 cent, 녹음 샘플 간격은 200 cent(온음). 모호한 "100~200 cents" 표기 제거. (§5.3)
- **순서 재편성.** '프로젝트 정체성 → 스택 → 소리 원천 검증 → 음향 아키텍처 → 기술 제약·정정 → 난이도 → UI → 코드 → 백엔드 → 오프라인 → 로드맵 → 다음 단계' 흐름으로 재배열.

> Assumption: 4개 문서의 작성 순서를 (① 초기 명세서 → ② 검증 사양서 → ③ 음향 엔진 설계서 → ④ 인계문)으로 추정하고, 가장 최신인 인계문(④)의 결정(키존 확정)을 최종 기준으로 삼았습니다. 실제 순서가 다르면 알려주세요.

## 3. 소리 원천(Sound Source) 검증 결과

음고를 cent 단위로 정밀 제어하는 자극 생성 방식 6가지를 교차검증한 결과입니다.

| 방식 | 음고 정밀도 | 음색 자연성 | 구현 난이도 | 주요 제약 및 검증 결과 |
| --- | --- | --- | --- | --- |
| 순수 파형 (DSP) | 초정밀 (1 cent) | 인공음(Sine/Saw) | 쉬움 | 0Byte, 기초 정밀 훈련용에 적합 |
| 단일 샘플 + Pitch Shift | 초정밀 (1 cent) | 변형 발생 | 보통 | **단독 사용 불가.** 광역 이동 시 다람쥐/다스베이더 현상 + 재생 시간 변형. 원음 근처(±2~3반음)만 자연스러움 |
| **키존 다중 샘플링 (하이브리드)** | 초정밀 (1 cent) | **높음** | 보통 | **[최종 선정]** 원음 품질 유지, 포먼트 변형 최소화 |
| 포먼트 합성 (DSP) | 초정밀 (1 cent) | 보통(로봇 모음) | 보통 | F0·포먼트 완전 독립 제어. 학술적 제어력 우수 |
| Web Speech API (TTS) | 낮음(상대 수치) | 보통 | 매우 쉬움 | `pitch` 0.0~2.0 상대값 → Hz/cent 지정 불가 → 부적합 |
| 신경망 TTS (WASM/WebGPU) | 낮음(Hz 지정 불가) | 매우 높음 | 어려움 | 정확한 F0 지정 미지원(속도만 조절), 대용량(수십 MB ~ 300MB+; 예: Piper ~75MB, Kokoro ~305MB) → 부적합 |

**단일 샘플 방식 관련 정정:**
- "음색 100% 유지" 주장은 **거짓**으로 판정. `AudioBufferSourceNode.playbackRate`는 포먼트·재생 길이를 함께 커플링시킴(테이프 배속 효과).
- 피치 유지 속성 `preservesPitch`는 `<audio>`(HTMLMediaElement)에만 있고 `AudioBufferSourceNode`에는 없음. 게다가 음고 훈련이 원하는 것과 **반대** 기능(피치를 고정해 버림)이라 사용 대상이 아님.

## 4. 음고 훈련 모듈 — 자극 생성 아키텍처

### 4.1 두 가지 훈련 모드

앱의 음고 훈련은 두 모드를 제공합니다.

1. **순수 파형 모드 (Sine DSP):** `OscillatorNode('sine')` 기반 초정밀 주파수 실시간 연산. 1 cent 분해능. 기초 음고 변별 훈련용. — *확정, 코드 구현 완료.*
2. **사람 목소리 모드 ("아~"):** 아래 §4.2가 최종안, §4.4가 현행 코드 구현체.

### 4.2 [최종 확정] 키존(Keyzone) 다중 샘플링 — 사람 목소리 자연음 경로

**개념:** 실제 "아~" 녹음을 여러 기준 음고로 확보하고, 그 사이만 소폭 시프트로 보간. 시프트 거리를 좁혀 포먼트 왜곡을 **구조적으로 회피**.

**주요 사양**
- 녹음 샘플 간격: **200 cent(온음)** — 예: C3, D3, E3…
- 최대 피치 시프트: 최근접 샘플 기준 **±100 cent(반음) 이내**
- 포먼트 변형 통제: 최대 시프트 시 포먼트 변형 약 6% 이내로 제한 → 피험자가 음고 변화 대신 음색 아티팩트를 단서(cue)로 쓰는 교란변수 차단
- 오디오 노드: 실제 녹음을 재생하므로 `AudioBufferSourceNode` 기반

**이상(자연성) vs 현 구현(실무) — 같은 자리에서 명시:**
- **이상(자연성 목표):** 키존 다중 샘플링. 검증 완료된 **최종 선정안**. 실제 사람 음성이라 자연성이 가장 높음.
- **현 구현/실무 제약:** 키존 경로는 **아직 코드화되지 않음**. 선행 작업으로 **음성 샘플 데이터셋 구축**(200 cent 간격 "아~" 녹음, 노이즈 제거, 루프 포인트 가공)이 필요. 데이터셋이 준비되기 전까지는 §4.4의 포먼트 합성(DSP)이 동작 가능한 대안.

### 4.3 평가(Assessment) / 훈련(Training) 이원화

임상·청각학적 타당도(psychophysical construct validity) 보장을 위해 검사 목적별로 동작을 분리합니다.

| 구분 | 평가(Assessment) | 훈련(Training) |
| --- | --- | --- |
| 소리 원천 | 목표 음고 **직접 녹음(shift = 0)** | 기준 음고 녹음 + 키존 보간 |
| 음고 제어 | 파일 1:1 매핑 | 최근접 샘플 + `detune`(cent) |
| 포먼트 변형 | **0%** (리샘플링 없음 → 실제로 무결) | ±100 cent 이내 (허용 오차 내) |
| 길이 통제 | 원본 고정 | Gain Envelope로 목표 시간 컷오프 |

```
[목표 주파수 (Hz) 입력]
        │
        ├── [평가 세트] ──> 1:1 매핑 직접 녹음 재생 (shift = 0, 포먼트 변형 0%, 완전 무결)
        │
        └── [훈련 세트] ──> 최근접 키존 샘플 선택 (간격 200 cent)
                            ├── detune 계산 (최대 시프트 ±100 cent 검증)
                            └── 지속 시간(Duration) 통제
```

### 4.4 [대안 / 현행 코드] 포먼트 합성 (Pure DSP)

- **구현:** `OscillatorNode('sawtooth')` + `BiquadFilterNode('bandpass')` 2개(F1 = 800Hz, F2 = 1200Hz, Q = 3.0) 중첩 → 성음 포먼트 공명 모사.
- **장점:** 0Byte, 완전 오프라인·실시간, F0·포먼트 독립 제어(연구 목적에 유리), 녹음 데이터셋 불필요.
- **대가:** 로봇 모음 음색(자연성 낮음). 그래서 §4.2 키존이 자연음 최종안이고, 이 경로는 **대안·현행 코드**로 유지.
- **현재 §8의 코드가 구현하는 것이 바로 이 경로**입니다.

## 5. Web Audio 기술 제약 및 반드시 유지할 정정 사항

> 이 절의 4개 항목은 임상 타당도 표현과 직결되므로 반드시 유지합니다.

### 5.1 `detune`의 실제 동작 (정정 1)

- `detune` ≠ 아티팩트 저감 수단. `detune`와 `playbackRate`는 **동일 리샘플링 메커니즘**을 공유:

$$\text{Effective Rate} = \text{playbackRate} \times 2^{\frac{\text{detune}}{1200}}$$

- 따라서 `detune`도 포먼트·길이를 똑같이 커플링. cent 단위 표기 문법일 뿐.
- 결론: **아티팩트 예산 = 최근접 샘플로부터의 총 cent 편차.** 포먼트 보존은 API 기능이 아니라 **±100 cent 제한 키존 구조**로 달성.

### 5.2 재생 길이(Duration) 커플링 — 검증 수치 (정정 2)

피치 변환 시 재생 속도가 바뀌어 지속 시간이 비대칭으로 변합니다. (기준 1000ms)

| 방향 | rate | 결과 길이 | 변화율 |
| --- | --- | --- | --- |
| 피치 업 (+1반음, +100 cent) | 1.05946 | 943.9ms | **−5.61%** |
| 피치 다운 (−1반음, −100 cent) | 0.94387 | 1059.5ms | **+5.95%** |

- **방향별 비대칭.** 단일 수치 "5.95%"는 다운 방향 최대값일 뿐, 업 방향은 −5.61%.
- 커플링 반영 길이 계산: `원본 길이 / 2^(detune/1200)`
- **제어 방식**
  - 피치 다운(길어짐): `GainNode` Envelope로 목표 시간에 맞춰 Fade-out 컷오프.
  - 피치 업(짧아짐): Zero-Crossing 기반 Crossfade Loop로 길이 연장 후 `GainNode` Envelope로 컷오프.

### 5.3 용어 표기 규칙 (정정 4)

- "±1반음" = 최근접 샘플로부터 최대 편차 **±100 cent(반음)**.
- 녹음 샘플 **간격 = 200 cent(온음)**.
- 모호한 "100~200 cents" 범위 표기 금지 → **"간격 200 / 최대 시프트 100 cent"**로 통일.

### 5.4 표현 주의 — 임상 타당도 (정정 3)

- **"지각 불가능"은 과잉 확언.** 100 cent = 포먼트 약 6% 이동. 작지만 단정 금지 → **"실용상 허용 오차 내"**로 표현.
  - 예외: 평가셋 shift = 0의 "포먼트 변형 0%"는 리샘플링이 없으므로 **사실**.
- **Loop 컷오프는 표준 샘플러 기법이나 루프 포인트 처리가 필요.** 피치업(짧아짐 → 루프 연장)은 제로크로싱/크로스페이드 루프로 클릭 방지 필요. **"손쉽게"는 낙관**.
- 스템 재생의 "100% 보존"도 분리 모델의 본질적 한계(잔향 누출 등)를 고려해 "분리된 원음 스템을 리샘플링 없이 그대로 재생"으로 완화 표현.

## 6. 적응형 난이도 엔진 (Adaptive Staircase)

- **기준음:** A4 (440Hz)
- **동작 순서:** 소리 A(기준) 1.0s ➔ 대기 0.5s ➔ 소리 B(비교) 1.0s
- **난이도 제어**
  - 연속 2회 정답 시: 격차 **10 cent 감소** (최소 10 cent까지, 난이도 상승)
  - 오답 시: 연속 정답 수 리셋 + 격차 **10 cent 증가** (최대 300 cent까지, 완화 · 문헌 프록시 잠정값)
  - cent → 주파수 변환: `f = f0 × 2^(cents/1200)`

> 참고(패턴 실무성): 이 방식(연속 정답 시 하강, 오답 시 상승하는 전환형 계단법)은 **청각·정신물리학 실험 및 앱에서 흔히 쓰이는** 표준 적응 절차입니다.

## 8. 음고 훈련 모듈 구현 코드 (`PitchTrainingModule.tsx`)

> ⚠️ **현행 코드의 범위:** 이 코드는 **DSP 합성 경로**(순수 파형 Sine + 포먼트 합성 "아~", §4.4)를 구현합니다. §4.2에서 최종 확정된 **키존 다중 샘플링(실제 녹음) 경로는 아직 미구현**이며, 그 핵심 함수 작성이 다음 작업입니다(§12).
>
> 패턴 실무성 메모:
> - `OscillatorNode` + `GainNode` Ramp Envelope로 클릭/팝 방지: **표준·흔한** Web Audio 패턴.
> - Bandpass 2개로 포먼트를 모사하는 방식: **실무에서는 드묾**. 상용 음성은 대개 실녹음 샘플이나 전용 보컬 합성을 사용하며, 이 코드는 단순 근사임.

```tsx
import React, { useState, useRef, useEffect } from 'react';
import {
  StyleSheet,
  View,
  Text,
  TouchableOpacity,
  Animated,
  Easing,
  SafeAreaView,
  StatusBar,
} from 'react-native';
import { AudioContext } from 'react-native-audio-api';

type TrainingMode = 'wave' | 'voice';
type GameState = 'idle' | 'playing' | 'answered';

export default function PitchTrainingModule() {
  const [mode, setMode] = useState<TrainingMode>('wave');
  const [gameState, setGameState] = useState<GameState>('idle');
  const [activeSound, setActiveSound] = useState<'none' | 'A' | 'B'>('none');

  const [centsDifference, setCentsDifference] = useState<number>(50);
  const [streak, setStreak] = useState<number>(0);
  const [isHigher, setIsHigher] = useState<boolean>(true);
  const [feedback, setFeedback] = useState<{ message: string; isCorrect: boolean } | null>(null);

  const waveAnimA = useRef(new Animated.Value(0)).current;
  const waveAnimB = useRef(new Animated.Value(0)).current;
  const audioCtxRef = useRef<AudioContext | null>(null);

  useEffect(() => {
    audioCtxRef.current = new AudioContext();
    return () => {
      if (audioCtxRef.current) {
        audioCtxRef.current.close();
      }
    };
  }, []);

  const centsToFreq = (baseFreq: number, cents: number) => {
    return baseFreq * Math.pow(2, cents / 1200);
  };

  const triggerWaveAnimation = (targetAnim: Animated.Value) => {
    Animated.loop(
      Animated.sequence([
        Animated.timing(targetAnim, {
          toValue: 1,
          duration: 300,
          easing: Easing.linear,
          useNativeDriver: true,
        }),
        Animated.timing(targetAnim, {
          toValue: 0,
          duration: 300,
          easing: Easing.linear,
          useNativeDriver: true,
        }),
      ]),
      { iterations: 3 }
    ).start();
  };

  const playTone = (freq: number, startTimeOffset: number, duration: number, soundType: TrainingMode) => {
    if (!audioCtxRef.current) return;
    const ctx = audioCtxRef.current;
    const now = ctx.currentTime + startTimeOffset;

    const osc = ctx.createOscillator();
    const gain = ctx.createGain();

    if (soundType === 'wave') {
      osc.type = 'sine';
      osc.frequency.setValueAtTime(freq, now);

      gain.gain.setValueAtTime(0.001, now);
      gain.gain.exponentialRampToValueAtTime(0.4, now + 0.05);
      gain.gain.exponentialRampToValueAtTime(0.001, now + duration - 0.05);

      osc.connect(gain);
      gain.connect(ctx.destination);
    } else {
      osc.type = 'sawtooth';
      osc.frequency.setValueAtTime(freq, now);

      const filter1 = ctx.createBiquadFilter();
      filter1.type = 'bandpass';
      filter1.frequency.setValueAtTime(800, now);
      filter1.Q.setValueAtTime(3.0, now);

      const filter2 = ctx.createBiquadFilter();
      filter2.type = 'bandpass';
      filter2.frequency.setValueAtTime(1200, now);
      filter2.Q.setValueAtTime(3.0, now);

      gain.gain.setValueAtTime(0.001, now);
      gain.gain.linearRampToValueAtTime(0.3, now + 0.1);
      gain.gain.linearRampToValueAtTime(0.001, now + duration - 0.05);

      osc.connect(filter1);
      osc.connect(filter2);
      filter1.connect(gain);
      filter2.connect(gain);
      gain.connect(ctx.destination);
    }

    osc.start(now);
    osc.stop(now + duration);
  };

  const handlePlaySound = () => {
    if (gameState === 'playing') return;

    setGameState('playing');
    setFeedback(null);

    const baseFreq = 440;
    const higher = Math.random() > 0.5;
    setIsHigher(higher);

    const targetFreq = higher
      ? centsToFreq(baseFreq, centsDifference)
      : centsToFreq(baseFreq, -centsDifference);

    setActiveSound('A');
    triggerWaveAnimation(waveAnimA);
    playTone(baseFreq, 0, 1.0, mode);

    setTimeout(() => {
      setActiveSound('none');
    }, 1000);

    setTimeout(() => {
      setActiveSound('B');
      triggerWaveAnimation(waveAnimB);
      playTone(targetFreq, 0, 1.0, mode);
    }, 1500);

    setTimeout(() => {
      setActiveSound('none');
      setGameState('idle');
    }, 2500);
  };

  const handleAnswer = (userThinksHigher: boolean) => {
    if (gameState === 'playing') return;

    const correct = userThinksHigher === isHigher;

    if (correct) {
      const newStreak = streak + 1;
      setStreak(newStreak);
      setFeedback({
        message: `🎉 정답입니다! B 소리가 ${centsDifference} Cents 더 ${isHigher ? '높았습니다' : '낮았습니다'}.`,
        isCorrect: true,
      });

      if (newStreak % 2 === 0 && centsDifference > 10) {
        setCentsDifference((prev) => Math.max(10, prev - 10));
      }
    } else {
      setStreak(0);
      setFeedback({
        message: `아쉽네요! B 소리가 더 ${isHigher ? '높았습니다' : '낮았습니다'}. 소리를 다시 느껴보세요.`,
        isCorrect: false,
      });

      setCentsDifference((prev) => Math.min(300, prev + 10));
    }

    setGameState('answered');
  };

  return (
    <SafeAreaView style={styles.container}>
      <StatusBar barStyle="light-content" backgroundColor="#12131C" />

      <View style={styles.header}>
        <Text style={styles.headerTitle}>🎵 음고 감각 적응 훈련</Text>
      </View>

      <View style={styles.tabContainer}>
        <TouchableOpacity
          style={[styles.tabButton, mode === 'wave' && styles.activeTab]}
          onPress={() => {
            setMode('wave');
            setFeedback(null);
          }}
        >
          <Text style={[styles.tabText, mode === 'wave' && styles.activeTabText]}>
            🌊 순수 파형 (DSP)
          </Text>
        </TouchableOpacity>

        <TouchableOpacity
          style={[styles.tabButton, mode === 'voice' && styles.activeTab]}
          onPress={() => {
            setMode('voice');
            setFeedback(null);
          }}
        >
          <Text style={[styles.tabText, mode === 'voice' && styles.activeTabText]}>
            🎤 사람 목소리("아~")
          </Text>
        </TouchableOpacity>
      </View>

      <View style={styles.infoRow}>
        <View style={styles.badge}>
          <Text style={styles.badgeText}>격차: {centsDifference} Cents</Text>
        </View>
        <View style={styles.badge}>
          <Text style={styles.badgeText}>🔥 연속 정답: {streak}회</Text>
        </View>
      </View>

      <View style={styles.visualizerCanvas}>
        <View style={styles.soundBox}>
          <Text style={styles.soundLabel}>소리 A (기준)</Text>
          <Animated.View
            style={[
              styles.waveBar,
              {
                backgroundColor: activeSound === 'A' ? '#00E5FF' : '#333A52',
                transform: [
                  {
                    scaleY: waveAnimA.interpolate({
                      inputRange: [0, 1],
                      outputRange: [0.3, 1.2],
                    }),
                  },
                ],
              },
            ]}
          />
        </View>

        <View style={styles.soundBox}>
          <Text style={styles.soundLabel}>소리 B (비교)</Text>
          <Animated.View
            style={[
              styles.waveBar,
              {
                backgroundColor: activeSound === 'B' ? '#FF6D00' : '#333A52',
                transform: [
                  {
                    scaleY: waveAnimB.interpolate({
                      inputRange: [0, 1],
                      outputRange: [0.3, 1.2],
                    }),
                  },
                ],
              },
            ]}
          />
        </View>
      </View>

      <TouchableOpacity
        style={[styles.playButton, gameState === 'playing' && styles.disabledButton]}
        onPress={handlePlaySound}
        disabled={gameState === 'playing'}
      >
        <Text style={styles.playButtonText}>
          {gameState === 'playing' ? '🔊 소리 감상 중...' : '▶️ 소리 듣기 (A ➔ B)'}
        </Text>
      </TouchableOpacity>

      <Text style={styles.questionText}>
        첫 번째 소리(A) 대비 두 번째 소리(B)의 높낮이는?
      </Text>

      <View style={styles.choiceRow}>
        <TouchableOpacity
          style={[styles.choiceButton, styles.highButton]}
          onPress={() => handleAnswer(true)}
          disabled={gameState === 'playing'}
        >
          <Text style={styles.choiceText}>⬆️ B 소리가 더 높음</Text>
        </TouchableOpacity>

        <TouchableOpacity
          style={[styles.choiceButton, styles.lowButton]}
          onPress={() => handleAnswer(false)}
          disabled={gameState === 'playing'}
        >
          <Text style={styles.choiceText}>⬇️ B 소리가 더 낮음</Text>
        </TouchableOpacity>
      </View>

      {feedback && (
        <View
          style={[
            styles.feedbackBox,
            feedback.isCorrect ? styles.correctBox : styles.wrongBox,
          ]}
        >
          <Text style={styles.feedbackText}>{feedback.message}</Text>
        </View>
      )}
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, backgroundColor: '#12131C', paddingHorizontal: 20 },
  header: { paddingVertical: 16, alignItems: 'center' },
  headerTitle: { fontSize: 20, fontWeight: 'bold', color: '#FFFFFF' },
  tabContainer: { flexDirection: 'row', backgroundColor: '#1E202F', borderRadius: 12, padding: 4, marginBottom: 16 },
  tabButton: { flex: 1, paddingVertical: 12, alignItems: 'center', borderRadius: 10 },
```

## 9. 백엔드 및 AI 스템 분리 파이프라인

### 9.1 백엔드 처리 당위성

- 딥러닝 음원 분리 모델(예: Demucs)의 연산 부하(FFT·복소수 행렬 계산)로 인해, 모바일 온디바이스 처리 시 OOM 앱 튕김·배터리 급소모·발열·긴 처리 시간(곡당 3~5분)이 발생할 수 있음 → **분리 연산은 백엔드 GPU 서버에서 수행**.
- GPU 서버(예: NVIDIA T4 / A10G) 활용 시 곡당 5~15초 내 분리 완료.

### 9.2 시스템 아키텍처 및 작업 흐름

```
[ RN Client ] ──(1) 음원 업로드 요청──> [ FastAPI Server ]
                                             │
                                     (2) Task Queue 등록
                                             ▼
                                   [ Redis / Celery ]
                                             │
                                     (3) GPU 작업 할당
                                             ▼
                                  [ GPU Worker (Demucs) ]
                                             │
                                     (4) 4-Stem 분리 (Vocals, Drums, Bass, Other)
                                             ▼
                                  [ AWS S3 Object Storage ]
                                             │
[ RN Local Storage ] <──(5) S3 URL 수신 및 다운로드──┘
```

### 9.3 스마트 음원 조절 플레이어 (Type A)

- 서버에서 미리 분리된 4개 스템 트랙을 다운로드/스트리밍하여 앱 내 동기화 재생.
- 각 트랙 `GainNode` 제어로 보컬 강조, 악기 트랙 조절, 잔향(Reverb) 필터링을 실시간 믹싱.
- **표현 정정:** "감동 100% 보존"이 아니라 **"분리된 원음 스템을 리샘플링 없이 그대로 재생"**. 분리 모델 자체의 잔향 누출 등 한계는 존재.

### 9.4 백엔드 운영 최적화

- **SHA-256 Audio Hashing:** 동일 음원 업로드 시 해시값을 조회해 GPU 재연산 없이 S3 URL 즉시 반환(0초).

## 12. 다음 단계 및 미해결 분기

**즉시 다음 작업 (사용자와 합의됨):**
목표 Hz를 입력받아 → 최근접 키존 샘플 선택 → `detune`(cent) 계산 → 재생 길이 계산하는 JS 함수 작성. (아직 미착수)

**착수 전 확인할 분기 (사용자 확정 필요):**
- 목표 음고가 **이산 소수**이면 직접 녹음(shift = 0)이 나을 수 있음(보간 불필요).
- 목표 음고가 **연속/다수**이면 키존 보간 적용.

**함수 설계 시 반영할 점:**
- 입력: 목표 Hz, 샘플 맵(각 샘플의 기준 Hz 또는 MIDI/note).
- 최근접 샘플: cent 거리 최소인 샘플 선택. `cent 거리 = 1200 × log2(target / sampleHz)`.
- detune 값 = 그 cent 거리 (**±100 cent 상한 검증 로직 포함**).
- 재생 길이: `원본 길이 / 2^(detune/1200)` (커플링 반영). 목표 길이 컷오프가 필요하면 Gain Envelope / loop 별도 처리.

**작성 규칙(사용자 선호):**
- 코드 제시 시 해당 패턴이 실무에서 흔한지/드문지 명시.
- 판단 기준은 카테고리 우선, 제품명은 예시(괄호).
- 질문에는 답부터 제시.
