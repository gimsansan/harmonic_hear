# 훈련 모드 역치 진행도 노출 위치 변경 — 결과

일시: 2026-08-08
대상: `app/training.tsx`
관련: `src/constants/theme.ts` (`STAIRCASE.THRESHOLD_MIN_REVERSALS`, `ASSESSMENT`), `src/components/ThresholdChart.tsx`, `app/stats.tsx`

## 문제 (사용자 보고에서 출발)

사용자가 세션을 3회 저장했는데 통계 화면의 역치 추이 그래프가 뜨지 않았다.
확인 결과 `총 3세션 · 역치 산출 0세션` — 세 세션 모두 `thresholdCents === null`.

원인 연쇄:

1. 훈련 모드는 `MIN_TRIALS_TO_END = 3`시행부터 `세션 종료 및 저장` 버튼을 노출한다 (`app/training.tsx:61`, `:545`).
2. 그 전에는 버튼 대신 **3칸 막대 + `1/3` 라벨**만 뜨고, 그 숫자가 무엇을 세는지 설명이 없었다 (`:554-568`).
3. 그래서 `3/3`이 "문항 3개를 다 풀었다 = 끝"으로 읽혔고, 사용자는 3시행에서 종료했다.
4. 그러나 역치는 반전 4회(`THRESHOLD_MIN_REVERSALS: 4`)가 필요하고, 최선의 정답/오답 배열에서도 **최소 8시행**이 든다.
5. 결과적으로 역치 없는 세션만 쌓였고, `ThresholdChart`는 값이 2개 미만이라 빈 상태로 남았다 (`ThresholdChart.tsx:30`).

사용자가 3개 제안 중 **3번(진행도를 종료 판단 지점으로 이동)만** 적용하도록 지시했다.

## 계획

- `MIN_TRIALS_TO_END`(3)와 `3/3` 막대, 종료 버튼 문구는 **건드리지 않는다** (1·2번 미적용).
- 역치 산출 진행도를 화면 위쪽 통계줄에서 **종료 영역 바로 위**로 옮긴다.
- 3시행을 넘겨 종료 버튼이 열린 뒤에도 계속 노출한다.
- "지금 끝내면 어떻게 되는지"를 문구에 명시하고, 달성 여부를 색으로 구분한다.

## 확인 못 한 것 (중요)

**에뮬레이터 화면에서 눈으로 확인하지 못했다.** 화면 표시 변경인데 렌더링을 못 봤으므로, 이 변경은 아직 "코드·번들 수준까지만" 검증된 상태다.

막힌 경위:

- 에뮬레이터(`emulator-5554`)는 떠 있고, `adb reverse tcp:8081`도 걸렸고, Metro는 이 프로젝트의 새 코드를 서빙 중(위 grep으로 확인).
- 그런데 설치된 APK는 **`com.rnhear.app`** (2026-08-06 설치)이고, 현재 `app.json`의 package는 **`com.vlondy.harmonitune`**. 앱 ID 정리(커밋 `44f6da9`) 이전 빌드다.
- 이 APK를 띄우면 스플래시(흰 화면)에서 멈추고 logcat에 `Couldn't connect to packager, will silently retry`만 반복. 3회 재시도 모두 동일.
- 재빌드(`npx expo run:android`)는 `reports/android-build-failure-handoff.md`에 기록된 기존 실패(`:react-native-audio-api:downloadPrebuiltBinaries`가 Git Bash에서 `mkdir: command not found` → exit 127)가 해결됐다는 근거가 없어 시도하지 않았다.

## 다음에 할 일

1. 재빌드 후 훈련 모드 1문항 진행 → 종료 영역 위 **주황 문구** 노출 확인.
2. 반전 4회 도달 시 **초록 전환** 확인.
3. 평가 모드에서도 같은 자리에 `방향 전환 n/8` 노출 확인.
4. 이 변경만으로 사용자가 3시행에서 끝내는 일이 줄었는지 확인. 안 줄면 제안 1·2번(막대 라벨 `저장 가능까지 0/3`, 버튼 문구 `여기까지 하고 저장`) 적용 검토.
