## 1. 가장 약한 경계 — 저장소에서 읽어 온 것

```
{AsyncStorage 글자} --JSON.parse--> as SessionResult[] --검사 없음--> [결과] [통계]
```

`TrainingStorage.ts:78`:

```ts
return JSON.parse(raw) as SessionResult[];
```

`as`는 **"이 모양이라고 치자"는 선언일 뿐, 실제로 그 모양인지 확인하지 않습니다.** 저장된 글자가 깨졌거나 옛날 버전 모양이면 타입 검사는 통과하지만 실행 중에 터집니다.

`getBestScore`(`:105`)는 `as`조차 없이 `JSON.parse` 결과를 그대로 돌려줍니다.

### 다만 위험이 낮은 이유가 있습니다

이 저장소에 값을 넣는 곳은 **이 앱의 `saveSession` 하나뿐입니다.** 서버에서 받아 오는 것도, 다른 앱이 쓰는 것도 아닙니다. `ask-types-contracts.md`가 말하는 "내가 통제 못 하는 외부 데이터"는 아닙니다.

위험은 **앱 버전이 올라가면서 모양이 달라지는 경우**로 좁혀집니다. 그리고 그 경우를 대비한 흔적이 실제로 있습니다.

```ts
baseFreq?: number;              // "구버전 세션에는 없을 수 있음"
clampCount?: number;            // "구버전 세션에는 없을 수 있음"
thresholdCents?: number | null; // "구버전 세션에는 없을 수 있음"
reversals?: number[];           // "구버전 세션에는 없을 수 있음"
```

`SessionManager.ts:34-55`. 물음표는 "없을 수도 있다"는 표시입니다.

### 읽는 쪽이 그 물음표를 제대로 열고 씁니다

| 어디 | 어떻게 |
|---|---|
| `result.tsx:82` | `session.reversals?.length ?? 0` |
| `result.tsx:83` | `previous?.thresholdCents ?? null` |
| `result.tsx:86` | `threshold != null && priorThreshold != null` 확인 후 계산 |
| `stats.tsx:137` | `stats?.bestThresholdCents != null ? ... : '-'` |
| `stats.tsx:242` | `session.thresholdCents != null ? ... : '-'` |
| `TrainingStorage.ts:165-168` | `typeof s.thresholdCents === 'number'`로 걸러냄 |

마지막 것이 가장 좋습니다 — `as`가 아니라 **실행 중에 실제로 값의 종류를 확인**합니다.

### 대비가 안 된 곳도 있습니다

`stats.tsx:198-200`:

```js
const accuracyPct = Math.round((session.correctCount / session.totalTrials) * 100);
```

`totalTrials`가 0인 세션이 있으면 `NaN%`가 그려집니다. 저장이 3문항 이상에서만 열리므로 0건 세션이 만들어지는 경로는 확인되지 않았지만, 막는 장치는 없습니다.

`result.tsx:92-95`의 `session.trials.reduce(...)`도 `trials`가 없으면 터집니다. `trials`는 물음표 없는 필수 필드라 항상 있다고 보는 것인데, 저장된 값을 실제로 검사하지 않으므로 보장은 아닙니다.

## 2. 약속을 우회한 곳 (`as` 단언)

`app/` 안에 `any`는 **없습니다.** `as`는 세 곳입니다.

| 어디 | 무엇 | 성격 |
|---|---|---|
| `TrainingStorage.ts:78` | `as SessionResult[]` | 검사 없이 믿음 |
| `training.tsx:548-551` | 아이콘 이름을 `as ComponentProps<typeof Feather>['name']` | 타입을 되돌리는 단언 |
| `AppSettingsStorage.ts:21` | `as ReferencePitchPreset[]` | **검사 함수를 만들기 위한** 단언 |

세 번째는 성격이 다릅니다 — 검사를 우회하는 게 아니라 검사 목록을 만드는 데 쓰입니다.

두 번째가 생긴 이유가 재밌습니다. `trainingFlow.ts:99`에서 아이콘 표를 이렇게 선언했습니다:

```ts
export const PLAY_BUTTON_ICON: Record<GameState, string> = { ... };
```

`string`으로 두면 화면 쪽에서 아이콘 이름 타입으로 되돌리는 단언이 필요해집니다.

그런데 `ModeTab.tsx:37`은 **같은 상황에서 단언 없이** 씁니다:

```ts
const TAB_ICON: Record<SoundMode, React.ComponentProps<typeof Feather>['name']> = { ... };
```

**같은 저장소 안에 두 방식이 섞여 있습니다.** 두 번째 방식이면 단언이 필요 없습니다.

## 3. 같은 개념이 두 번 정의된 곳

`app/stats.tsx:39-48`에 `StorageStats`라는 인터페이스가 있습니다.

```ts
interface StorageStats {
  totalSessions: number;
  totalTrials: number;
  overallAccuracy: number;
  sessionsWithThreshold: number;
  bestThresholdCents: number | null;
  latestThresholdCents: number | null;
  bestMinCents: number | null;
  averageReactionMs: number | null;
}
```

그런데 이 모양은 `TrainingStorage.getStats()`의 반환 타입과 **같은 내용을 다시 적은 것**입니다 (`TrainingStorage.ts:131-144`).

`ask-types-contracts.md`가 말하는 **"같은 개념을 여러 타입으로 중복 정의"**입니다. 저장소 쪽이 필드를 하나 늘리거나 이름을 바꿔도 화면 쪽 선언은 안 따라옵니다. 둘이 어긋나도 아무도 모릅니다.

공유 타입은 **원본 하나**여야 한다는 것이 이 축의 기본입니다.


세 가지가 눈에 띕니다.

**`clampFreq`가 잘랐는지까지 같이 돌려줍니다.** 값만 돌려주면 잘린 걸 아무도 모릅니다. `StaircaseEngine`이 그 표시를 받아 횟수를 셉니다 (`:169-177`). 계약 설계가 목적에 맞게 되어 있는 예입니다.

**`getState()`와 `getReversals()`가 복사본을 줍니다.** 밖에서 받은 값을 고쳐도 엔진 안은 안 바뀝니다. 원본을 하나로 지키는 장치이고, **테스트로도 고정돼 있습니다** (`StaircaseEngine.test.ts:53`).

**실패를 알리는 계약이 하나뿐입니다.** `saveSession`만 `boolean`을 돌려줍니다. `AppSettingsStorage`의 쓰기 3개와 `TrainingStorage.clearAll`은 `Promise<void>`라 실패를 알릴 수단 자체가 없습니다(→ [#4 에러 처리](./파악_4_에러처리_2026-08-21.md)).

`updateConfig`도 비슷합니다 — 세션 중이면 거부하는데, 돌려주는 값이 `void`라 부르는 쪽은 거부됐는지 모릅니다 (`SessionManager.ts:264-270`).

## 8. 이 축에서 눈에 띈 것

**타입 정의가 있어야 할 자리에 있습니다.** `GameState`는 `trainingFlow.ts`, `SessionResult`는 `SessionManager.ts`, `SoundMode`는 `AudioEngine.ts`, 프리셋은 `theme.ts`. 각 개념의 주인이 자기 타입을 정의합니다.

**`as const`를 일관되게 씁니다.** `theme.ts`의 값 표가 전부 `as const`라 값이 리터럴로 좁혀집니다. `StaircaseEngine.ts:100-101`에 그 때문에 생긴 처리(리터럴을 `number`로 넓히기)와 이유 주석까지 있습니다.

**약한 자리는 저장소 경계 하나입니다.** `as SessionResult[]`. 다만 그 저장소에 쓰는 것도 이 앱 자신이라 외부 데이터만큼 위험하지는 않고, 물음표 필드로 버전 차이를 대비해 두었습니다.

**중복 정의 하나** (`StorageStats`)와 **일관되지 않은 두 자리**(`Readonly<>` 유무, 아이콘 타입 선언 방식)가 눈에 띕니다. 셋 다 동작에는 영향이 없지만, 나중에 어긋날 자리입니다.
