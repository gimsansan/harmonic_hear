# 소리 모드 탭 잠김 표시 추가 — 결과

일시: 2026-08-08
대상: `src/components/ModeTab.tsx`, `app/training.tsx`
관련: `reports/voice모드_음량_조사_2026-08-08.md`

## 문제

사용자 보고: "모드를 토글하는 것도 안 되고 있다."

버그가 아니라 **의도된 잠금이 화면에 드러나지 않은 것**이다.

`app/training.tsx:353`:

```ts
const handleSoundModeChange = useCallback(
  (newMode: SoundMode) => {
    if (isSessionActive) return;   // ← 세션 중이면 조용히 무시
    setSoundMode(newMode);
```

세션 중 소리 종류가 바뀌면 그 세션의 자극 조건이 섞여 측정값을 비교할 수 없으므로, 잠그는 것 자체는 맞다. 문제는:

1. `ModeTab`에 `disabled` 개념이 아예 없었다 — 평소와 똑같이 눌리는 모양이다.
2. 눌러도 아무 반응이 없고 이유도 안 나온다 → **고장으로 읽힌다.**
3. `소리 듣기`를 누르면 세션이 자동 시작되므로(`handleNextRound`), **첫 재생 직후부터** 탭이 죽는다. 사용자가 이 상태를 만나기가 매우 쉽다.

## 계획

- 잠금 규칙 자체는 **바꾸지 않는다** (측정 타당도상 필요).
- `ModeTab`에 `disabled` / `disabledReason`을 받아 잠김을 눈에 보이게 한다.
- 이유를 문장으로 표시한다.

잠금 조건(`isSessionActive`)과 `handleSoundModeChange` 로직은 **변경하지 않음**.

## 확인 못 한 것

**잠김 표시가 실제로 어떻게 보이는지 눈으로 확인하지 못했다.**

이 변경을 넣은 직후부터 에뮬레이터가 앱을 **검은 화면으로만** 그린다. 원인은 앱이 아니다:

- JS는 정상 실행 중 — `Running "main"`, `SafeAreaView` 경고까지 정상 출력, JS 예외 0건.
- logcat에 `HwcComposer: getLuts failed ... UNSUPPORTED (8)` — 에뮬레이터 컴포지터 오류.
- 같은 시점에 오디오 HAL도 `pcm_writei failed ... I/O error`를 566회 이상 반복.

즉 **에뮬레이터가 그래픽·오디오 양쪽에서 degraded 상태**다. 변경 직전까지는 같은 에뮬레이터에서 화면이 정상 렌더됐고(역치 진행도 문구 확인 완료), 그 사이 코드 변경은 이 `ModeTab` 수정뿐이지만 JS 예외가 전혀 없으므로 인과관계는 없다고 본다.

## 다음에 할 일

1. 에뮬레이터 **콜드 부트** 후 재확인:
   `adb emu kill` → Android Studio Device Manager에서 `Cold Boot Now` (또는 `emulator @Pixel_7 -no-snapshot-load`).
2. 훈련 진입 → `소리 듣기` 1회 → 탭이 흐려지고 `🔒`와 이유 문구가 뜨는지 확인.
3. 세션 종료 후 탭이 다시 살아나는지 확인.
4. 소리가 들리게 되면 wave / voice 음량 차이를 **귀로** 확인 (`voice모드_음량_조사_2026-08-08.md` 참조).
