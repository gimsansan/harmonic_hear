## 먼저 — 이 앱에는 서버가 없습니다

`fetch`, 요청 함수, 서버 상태 라이브러리가 코드 어디에도 없습니다.
데이터는 전부 기기 안 저장 공간(AsyncStorage)에 있습니다.

## 1. 세션 기록 1건 — 이 앱의 주된 데이터

```
[훈련: 세션 종료 및 저장]
    --> (메모리 세션)@SessionManager
    --> {AsyncStorage · sessions}
    --> [결과]  /  [통계]
```

**언제 나가나** — 사용자가 "세션 종료 및 저장"을 누를 때, 또는 평가 모드가 자동 종료될 때 (`app/training.tsx:216`).

**보낸 뒤 무엇을 갱신하나** — `[결과]` 화면으로 이동하고, **그 화면이 저장소를 다시 읽습니다** (`app/result.tsx:47`). 방금 저장한 값을 그대로 넘겨주지 않고 저장소를 정본으로 삼습니다. 저장이 실제로 됐는지가 화면에 그대로 드러나는 구조입니다.

**실패하면** — `saveSession`이 `false`를 돌려주고, 화면은 팝업으로 알린 뒤 그 자리에 머무릅니다. 이 앱에서 **실패를 사용자에게 알리는 유일한 경로**입니다(→ [#4 에러 처리](./파악_4_에러처리_2026-08-21.md)).

**빈 값이면** — `getAllSessions()`가 `[]`를 돌려주고, `[통계]`는 "저장된 훈련 기록이 없습니다" 상자를 보여 줍니다.

**로딩 중에는** — 따로 표시가 없습니다. `[통계]`는 당겨서 새로고침할 때만 도는 표시가 보입니다.

**중복 전송을 막나** — 종료 버튼에 잠금이 없습니다. 다만 저장에 성공하면 곧바로 `replace`로 화면을 떠나므로 실질적으로 두 번 누르기 어렵습니다.

**200건 상한** — `TrainingStorage.ts:38-41`에서 200건이 넘으면 오래된 것부터 버립니다. 이유가 주석(`:17-22`)에 있습니다 — 세션 하나에 시행 기록이 통째로 들어가서, 무제한으로 쌓이면 열쇠 하나가 수 MB까지 커져 읽기·쓰기가 눈에 띄게 느려집니다.

**진짜 출처(원본)가 어디냐** —

| 시점 | 원본 |
|---|---|
| 세션 진행 중 | **메모리** (`SessionManager` 안) |
| 세션 종료 후 | **AsyncStorage** |

이 둘이 겹치는 구간은 없습니다. 끝나야 저장되고, 저장돼야 읽힙니다.

## 2. 기준음 프리셋 (표준 440Hz / 중역 330Hz / 저역 262Hz)

```
[설정: 프리셋 누름] --> {AsyncStorage · reference_pitch_preset}

{저장소} --화면 진입 시--> (baseFreq)@훈련화면 --> AudioEngine 재생 주파수
{저장소} --세션 시작 시--> SessionManager 설정 --> StaircaseEngine
```

**언제 읽나** — `[훈련]` 화면에 들어올 때마다 한 번(`training.tsx:164`), 세션을 시작하는 순간 한 번 더(`:190`). 두 번 읽는 이유는 아래에 있습니다.

**세션 중에는 반영하지 않습니다.** `isSessionActiveRef.current`가 참이면 읽고도 화면에 안 씁니다 (`training.tsx:163`). 세션 도중에 기준음이 바뀌면 그 세션의 측정값을 앞뒤로 비교할 수 없기 때문입니다. `SessionManager.updateConfig`도 활성 세션이면 거부합니다 (`SessionManager.ts:265`).

**실패·잘못된 값이면** — `'standard'`(440Hz)로 떨어집니다 (`AppSettingsStorage.ts:37-42`).

**이 앱에서 유일하게 저장된 값을 실제로 검사하는 곳입니다.** `isValidPreset`이 저장소에서 읽은 글자가 세 프리셋 중 하나인지 확인합니다 (`:24-26`). 다른 데이터는 이런 검사가 없습니다(→ [#5 타입·계약](./파악_5_타입계약_2026-08-21.md)).

## 3. 진동(햅틱) 설정

```
[설정: 스위치] --즉시--> (enabled)@haptics 모듈
              --저장--> {AsyncStorage · haptics_enabled}

{저장소} --설정 화면 진입--> (enabled)@haptics 모듈
{저장소} --훈련 화면 진입--> (enabled)@haptics 모듈
```

값이 **두 군데**에 있습니다. 저장소가 원본이고, `src/utils/haptics.ts:12`의 모듈 변수 `let enabled`가 그 사본입니다.

사본을 맞추는 지점이 **세 곳**입니다.

| 어디 | 언제 |
|---|---|
| `settings.tsx:50` | 설정 화면에 들어올 때 |
| `settings.tsx:60` | 스위치를 조작할 때 (저장보다 먼저) |
| `training.tsx:162` | 훈련 화면에 들어올 때 |

훈련 화면에서도 맞추기 때문에, 설정을 바꾸고 바로 훈련에 들어가면 반영됩니다.

**실패하면** — 읽기 실패 시 "켜짐"으로 봅니다 (`AppSettingsStorage.ts:67`).

**쓰기 실패는 아무도 모릅니다.** `setHapticsEnabled`가 `Promise<void>`라 실패를 알릴 방법이 없습니다.

## 4. 첫 실행 안내를 봤는지

```
{AsyncStorage · onboarding_done} --> [홈]의 갈림길

[볼륨 안내: 시작 또는 건너뛰기] --> {저장소} = true
[설정: 다시 보기] --> {저장소} = false --> [볼륨 안내]
```

**언제 읽나** — `[홈]`에서 훈련 버튼을 누를 때(`index.tsx:27`), 그리고 **화면에 들어올 때 미리 한 번 더**(`index.tsx:32-36`).

미리 읽는 이유가 주석에 있습니다 — "첫 진입 시 미리 확인해 두어 탭 반응이 느려지지 않게 한다". 버튼을 눌렀을 때 저장소 읽기를 기다리느라 반응이 늦지 않게 하려는 것입니다. 읽은 값을 쓰지 않고 버리는 코드(`void`)라, 목적이 순전히 예열입니다.

**실패하면** — `false`(= 아직 안 봤음)로 봅니다 (`AppSettingsStorage.ts:84`). 안내를 한 번 더 보여 주는 쪽이 안전하다는 선택입니다.

## 5. 최고 기록 (`best_score`)

```
[훈련: 저장] --> {AsyncStorage · best_score}   (갱신만)
{best_score} --> 읽는 화면 없음
```

**읽어서 확인한 사실**: 이 열쇠는 저장·갱신은 되지만(`TrainingStorage.ts:49-62`), `getBestScore()`를 부르는 곳은 `saveSession` 자기 자신뿐입니다. `app/` 어느 화면도 이 값을 읽지 않습니다.

통계 화면이 보여 주는 "최고 역치"는 이 열쇠가 아니라, `getStats()`가 세션 전체를 그때그때 훑어 계산한 값입니다.

또 하나 — 이 열쇠가 담는 것은 `minCentsAchieved`(세션 중 도달한 최솟값)인데, `SessionManager.ts:56-59` 주석에 "극단값이라 운에 흔들립니다. 대표 지표로 쓰지 마세요"라고 적혀 있습니다. **대표 지표로 쓰지 말라는 값을 담은 열쇠가, 실제로 아무 데서도 안 읽힙니다.**

## 6. 통계 요약

```
{AsyncStorage · sessions} --전체 훑어 계산--> (stats)@통계화면 --> [통계] 타일 3개
{AsyncStorage · sessions} --최근 10건--> (recentSessions)@통계화면 --> [세션 목록] + [역치 그래프]
```

**언제 읽나** — `[통계]` 화면에 들어올 때마다(`stats.tsx:70`), 아래로 당겨 새로고침할 때(`:108`).

**캐시가 없습니다.** 들어올 때마다 저장소를 두 번 읽고 다시 계산합니다.

**로딩 중에는** — `refreshing`이 참인 동안 당김 표시가 돕니다. `finally`에서 확실히 꺼집니다(`:66`).

**실패하면** — `console.error`만 찍고 `stats`가 `null`로 남아 타일이 전부 `-`가 됩니다. "못 읽었다"와 "기록이 없다"가 구분되지 않습니다(→ [#4](./파악_4_에러처리_2026-08-21.md)).

**계산했지만 화면이 안 쓰는 값이 둘 있습니다** — `bestMinCents`, `latestThresholdCents`. `stats.tsx:44-46`에 타입으로는 적혀 있지만 화면 어디에도 그려지지 않습니다.

### 그래프에 들어가는 값

```
(recentSessions) --뒤집기(시간순 복원)--> --thresholdCents만 뽑기--> --숫자인 것만 남기기--> [ThresholdChart]
```

`stats.tsx:116-119`. 목록은 최근순이라 그래프용으로 다시 뒤집습니다.

`typeof v === 'number'`로 거르기 때문에, 역치가 안 나온 세션과 옛날 버전 세션은 그래프에서 빠집니다. 남은 값이 2개 미만이면 그래프 대신 안내 상자가 나옵니다 (`ThresholdChart.tsx:47`).

## 7. 한 라운드의 주파수 — 저장되지 않는 데이터

```
(centsDifference)@StaircaseEngine
    --prepareRound: 위/아래 추첨--> centsToFreq(baseFreq, ±cents)
    --clampFreq(200~2000Hz)--> (targetFreq)@StaircaseEngine
    --> AudioEngine.playSequence()
    --> [소리 B]
```

**앱을 끄면 사라집니다.** 저장되지 않습니다.

**한도를 벗어나면 잘라내고 그 횟수를 셉니다** (`StaircaseEngine.ts:169-177`). `clampFreq`가 잘린 값만이 아니라 **잘렸는지 여부까지** 같이 돌려주기 때문에 셀 수 있습니다. 그 횟수는 세션 결과에 `clampCount`로 담겨 저장됩니다.

**"다시 듣기"는 `prepareRound`를 부르지 않습니다** (`training.tsx:318-322`). 그래서 방향과 목표 주파수가 그대로 유지됩니다. 이 동작은 테스트로 고정돼 있습니다(`SessionManager.test.ts:20`).

### 반응 시간이라는 데이터

```
[B 재생 끝] --openResponseWindow()--> (측정 시작 시각)@SessionManager
[답변] --지금 - 시작 시각--> (reactionTimeMs) --> 시행 기록 --> {저장소}
```

측정을 **자극 재생이 끝난 뒤**부터 시작합니다 (`SessionManager.ts:142-144`). 라운드를 준비할 때가 아닙니다 — 그러면 소리 듣는 2.5초가 반응 시간에 섞입니다.

다시 듣기를 하면 **마지막 재생이 끝난 시점으로 갱신**됩니다. 답변한 뒤에는 창을 닫아(`:204`) 0으로 만듭니다.

측정 창이 안 열린 채 답이 들어오면 `0`을 남깁니다 (`:188`). 이 네 가지가 전부 테스트로 고정돼 있습니다.
