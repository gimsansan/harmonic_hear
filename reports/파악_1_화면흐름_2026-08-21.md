## 1. 화면 사이 이동

```
[홈] --훈련 시작(안내 이미 봤음)--> [훈련]
[홈] --훈련 시작(첫 실행)--> [볼륨 안내]
[홈] --통계 카드--> [통계]
[홈] --설정 카드--> [설정]

[볼륨 안내] --훈련 시작--> [훈련]           (replace: 뒤로 눌러도 안 돌아옴)
[볼륨 안내] --건너뛰기--> [홈]              (replace)

[훈련] --뒤로--> [직전 화면]
[훈련] --세션 종료 및 저장(성공)--> [결과]    (replace)
[훈련] --세션 종료 및 저장(실패)--> [훈련]    (화면 안 바뀜, 팝업만)

[결과] --한 세션 더--> [훈련]
[결과] --통계 보기--> [통계]
[결과] --홈으로--> [홈]

[통계] --뒤로--> [직전 화면]
[통계] --훈련하러 가기(기록 0건일 때만)--> [훈련]

[설정] --뒤로--> [직전 화면]
[설정] --볼륨 맞추기 안내 다시 보기--> [볼륨 안내]
```

읽어서 확인한 것 두 가지입니다.

**`replace`와 `push`가 구분돼 있습니다.** 볼륨 안내를 마칠 때와 세션을 끝낼 때는 `replace`라, 뒤로 가기를 눌러도 그 화면으로 되돌아가지지 않습니다 (`app/training.tsx:230`, `app/onboarding.tsx:79`, `:84`). 이미 답을 낸 세션 화면으로 돌아가는 길을 막아 둔 것입니다.

**저장이 실패하면 화면을 옮기지 않습니다.** `app/training.tsx:218-227`에서 저장 실패 시 팝업만 띄우고 `return` 합니다. 결과 화면으로 넘어가면 저장 안 된 세션이 저장된 것처럼 보이기 때문입니다.

## 2. 훈련 화면 **안**의 단계

훈련 화면은 라우팅 없이 `gameState` 하나로 보이는 것이 바뀝니다. 그 규칙은 화면 파일이 아니라 `src/training/trainingFlow.ts`에 순수 함수로 따로 빠져 있습니다.

```
[대기] --재생 버튼--> [소리 재생 중] --재생 끝--> [답변 대기] --답변--> [답변함]
                          ▲                        │                     │
                          └────다시 듣기────────────┘                     │
                          └──────────────새 문제─────────────────────────┘

[소리 재생 중] --앱 이탈·통화--> [중단됨] --새 문제--> [소리 재생 중]
[답변 대기]   --앱 이탈·통화--> [중단됨]
```

**[답변 대기]에서만 답을 받습니다.** `canSubmitAnswer`가 `'waiting'` 하나에만 참을 돌려줍니다 (`trainingFlow.ts:42`). 주석에 이유가 적혀 있습니다 — [답변함]에서도 받으면 정답을 본 뒤 같은 문제에 반복해서 답해 점수를 만들 수 있습니다.

**같은 버튼이 두 가지로 동작합니다.** [답변 대기]에서는 "다시 듣기"(같은 문제 그대로), 그 외에는 "새 문제"입니다 (`app/training.tsx:326`). 사용자가 "다시 듣기"라고 생각하고 누른 버튼이 정답을 다시 뽑아 버리면 안 되기 때문입니다.

**[중단됨]에서는 다시 듣기가 아닙니다.** 소리를 일부만 들었을 수 있어, 같은 문제를 다시 주면 그 일부가 힌트로 남습니다 (`trainingFlow.ts:51-52`). 그래서 새 문제로 갑니다.

**재생 중에는 버튼이 잠깁니다.** `canPressPlay`가 `'playing'`에서만 거짓입니다 (`trainingFlow.ts:59`).

### 단계마다 화면에 뜨는 것

| 단계 | 재생 버튼 문구 | 답변 버튼 | 추가로 보이는 것 |
|---|---|---|---|
| 대기 | 소리 듣기 (A → B) | 잠김 | — |
| 소리 재생 중 | 소리 감상 중… | 잠김 | A 또는 B 칸이 움직임 |
| 답변 대기 | 다시 듣기 (A → B) | **열림** | — |
| 답변함 | 다음 소리 듣기 (A → B) | 잠김 | 훈련 모드: 정답 카드 + B의 실제 Hz<br>평가 모드: "답변이 기록되었습니다" |
| 중단됨 | 새 문제로 다시 듣기 (A → B) | 잠김 | "소리를 놓쳐 이번 문제는 기록하지 않았습니다" |

문구 표는 `trainingFlow.ts:90-118`에 세 벌 있습니다 — 화면용, 아이콘용, 스크린리더용. 스크린리더용을 따로 둔 이유도 주석에 있습니다(아이콘과 짝지어 읽히는 화면 문구는 소리로 들으면 어색해서).

### 세션 중에는 잠기는 것

| 무엇 | 어디 | 잠긴 티를 내나 |
|---|---|---|
| 소리 종류 탭 (파형/목소리) | `ModeTab` | **낸다** — 자물쇠 아이콘 + 이유 문구 |
| 세션 모드 탭 (훈련/평가) | `training.tsx:458` | 흐리게만 |

`ModeTab.tsx:25-33`에 이유가 적혀 있습니다 — 잠긴 것을 화면에 안 드러내면 "눌러도 아무 일이 없는 고장"으로 읽힙니다.

### 종료 버튼이 열리는 조건

3문항을 채워야 "세션 종료 및 저장" 버튼이 뜹니다. 그전에는 3칸짜리 진행 막대가 보입니다 (`training.tsx:648-675`).

그 바로 위에 **역치 진행도 한 줄**이 붙습니다 (`:606-645`). 종료를 누르기 직전에 "아직 역치가 안 나왔다"를 보여 주기 위한 자리라고 주석에 적혀 있습니다.

## 5. 이 축에서 눈에 띈 것

**화면 규칙이 화면 파일 밖에 있습니다.** 보통 `useState`와 `if`로 화면 파일 안에 흩어져 있을 규칙이 `trainingFlow.ts` 한 파일에 순수 함수로 모여 있습니다. 그래서 **테스트로 고정할 수 있습니다** — 실제로 15개 항목이 이 규칙을 지키고 있습니다([#7 테스트](./파악_7_테스트_2026-08-21.md) 참고).

**반대로 `app/` 7개 화면 파일에는 테스트가 하나도 없습니다.** 규칙은 지켜지지만, 화면이 그 규칙을 실제로 그렇게 쓰는지는 아무도 확인하지 않습니다.

**`[결과]` 화면에는 나가는 길이 세 개인데, 데이터를 못 받았을 때 나가는 길이 없습니다.** "결과를 불러오는 중..." 화면에는 버튼이 하나도 없습니다 (`result.tsx:70-78`). 자세한 것은 [#4 에러 처리](./파악_4_에러처리_2026-08-21.md)에 있습니다.

## 확인 못 한 것

- **실기기·에뮬레이터에서 돌려 보지 않았습니다.** 위 화살표는 전부 코드를 읽어 그린 것이고, 실제로 그렇게 넘어가는지는 확인하지 않았습니다.
- **`StyleSheet.create({...})` 안의 값은 읽지 않았습니다.** 화면 파일 5개와 컴포넌트 파일 5개에 해당합니다.
- **`expo-router`가 파일을 어떻게 라우트로 잡는지** 설정 파일(`app.json` 등)로 확인하지 않았습니다. 파일 이름과 `router.push('/…')` 경로가 맞는다는 전제로 그렸습니다.
- 뒤로 가기(`router.back()`)가 실제로 어느 화면으로 가는지는 **직전 화면에 따라 달라지므로** 하나로 그리지 않았습니다.
