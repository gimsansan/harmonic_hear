# 클리니컬 라이트 리디자인 — HTML 시안을 RN 화면으로 변환

일시: 2026-08-11
대상: `app/` 전체 화면 6개, `src/components/` 5개, `src/constants/theme.ts`
관련: Claude Design 프로젝트 `HarmoniTune 화면 구조 정리`(`97cfae29-7583-4c46-a0ef-6f5d3386cf9c`)의 `HarmoniTune.dc.html`

## 계획

디자인 프로젝트의 `HarmoniTune.dc.html`은 390×844 프레임 6개(홈·훈련·평가·통계·설정·결과)를
어두운 네이비에서 **라이트 클리니컬 톤**으로 바꾼 시안이다. 기존 앱의 화면 구성과 6개가 1:1로
대응하므로, 새 화면을 만들지 않고 **기존 화면을 이 스펙으로 다시 칠하는** 방향을 택했다.

같은 프로젝트의 `support.js`도 읽었다. 첫 줄이 `// GENERATED from dc-runtime/src/*.ts`인
디자인 캔버스 렌더링 런타임(React createElement 래퍼·`<x-dc>` 파서)이고 디자인 값은 없다.
변환에 반영할 내용이 없어 참조만 하고 끝냈다.

순서:

1. `theme.ts`의 토큰 값을 라이트 팔레트로 교체한다. 토큰 **이름**을 유지하면 나머지 화면이
   자동으로 따라온다.
2. 시안에 있는 새 개념(연한 프라이머리 면, 짙은 강조 패널, 카드 내부 구분선)만 토큰을 추가한다.
3. 화면별로 레이아웃을 시안 구조에 맞춘다. 로직은 손대지 않는다.

## 시안과 일부러 다르게 한 것

세 가지는 시안 값을 그대로 쓰지 않았다.

1. **회색·오렌지·빨강의 명도를 낮췄다.** `theme.ts`는 원래 토큰마다 대비를 주석으로 적어 두고
   있었고, "규제 고지문이 이 색을 쓰므로 AA 아래로 내리지 마세요"라는 조건까지 달려 있었다.
   시안 값 중 본문에 쓰이는 것들이 라이트 배경에서 AA(4.5:1)에 못 미쳐, 색 계열은 유지한 채
   명도만 조정했다.

   | 용도 | 시안 값 | 배경 대비 | 채택 값 | 대비 |
   | --- | --- | --- | --- | --- |
   | 보조 텍스트 | `#6B7A90` | 4.4:1 | `#55637A` | 5.6:1 |
   | 작은 회색 라벨 | `#8A96A8` | 3.0:1 | `#5F6E85` | 4.8:1 |
   | 오렌지 **텍스트** | `#E8703A` | 3.1:1 | `#B8511E` | 5.0:1 |
   | 초기화 버튼 | `#D64545` | 3.9:1 | `#C0392B` | 4.8:1 |

   오렌지는 면·테두리·아이콘용(`secondary` `#E8703A`, 시안 그대로)과 텍스트용
   (`secondaryText` `#B8511E`)을 나눴다. 시안의 `#9AA6B8`은 `textMinimal`로 남겨 두되
   기존 주석대로 **장식 전용**이다.

2. **역치 그래프의 y축 뒤집기를 유지했다.** 시안은 값이 30→21로 좋아지는 구간에서 선이
   **아래로** 내려간다. 기존 `ThresholdChart`는 "그래프가 우상향하면 좋아지는 것으로 읽히게"
   라는 주석과 함께 y축을 뒤집어 두고 있었다. 이건 시각 스펙이 아니라 판단이라 보고 그대로 뒀다.
   대신 카드 각주에 "위로 갈수록 낮은 값이라, 선이 올라가면 좋아지는 중"이라고 적어 뒀다.

3. **이모지를 아이콘으로 바꿨다.** 시안이 전부 선 아이콘(SVG)이라 이모지를 남기면 톤이 섞인다.

## 확인 못 한 것

- **훈련·평가·결과·온보딩 화면의 실제 렌더링.** 이 네 화면은 `AudioEngine`을 거치는데,
  에뮬레이터에서 `Failed to install react-native-audio-api: The native module could not be found.`
  (`AudioEngine.ts:13`)가 떠 진입이 막힌다. **이번 변경과 무관한 환경 문제**다 —
  같은 APK에서 홈·통계·설정은 정상 렌더링되고, 이번 작업은 오디오 코드를 건드리지 않았다.
- 역치 추이 **그래프 본체**. 저장된 9세션 모두 역치가 없어(`역치 산출 0세션`) 히어로 카드의
  빈 상태만 확인했다. 선·면적·마지막 점 강조가 그려지는 경로는 미확인.
  (`SkPath.copy()`는 타입 정의에 존재함을 확인했다 — `Path.d.ts:280`)
- 소리. 실제 청취 확인은 하지 않았다.
- 실기기. 에뮬레이터에서만 봤다.

### 재빌드로도 못 뚫은 이유 (다음 사람을 위한 기록)

`./gradlew assembleDebug`는 **성공했다** (`BUILD SUCCESSFUL in 18m 40s`).
네이티브 쪽도 문제가 없다:

```
unzip -l app-debug.apk | grep audio-api
  lib/arm64-v8a/libreact-native-audio-api.so      (6.8 MB)
  lib/armeabi-v7a/libreact-native-audio-api.so    (4.3 MB)
  lib/x86/libreact-native-audio-api.so            (7.3 MB)
  lib/x86_64/libreact-native-audio-api.so         (7.2 MB)
```

`android/build/generated/autolinking/autolinking.json`에도 `react-native-audio-api`가 들어 있다.

막힌 지점은 **설치**다. `adb install -r -d`가 `Success`를 반환하는데 실제로는 반영되지 않는다:

```
adb install -r -d android/app/build/outputs/apk/debug/app-debug.apk
  → Performing Streamed Install
    Success

adb shell pm path com.vlondy.threadsclone
  → .../base.apk   113,600,322 bytes   2026-08-09 14:27   ← 안 바뀜
로컬 빌드 산출물                        343,399,384 bytes
```

`/data` 여유 공간은 1.8 GB로 부족하지 않다. force-stop 후 재실행해도 같다.
즉 **에뮬레이터가 새 APK를 받아들이지 않는 상태**이고, 이건 앱 코드 문제가 아니다.
[[android-device-verification-blocked]]에 적힌 절차대로 콜드 부트
(`adb emu kill` → `emulator @Pixel_7 -no-snapshot-load`)부터 다시 시도해야 한다.

## 다음에 할 일

- 에뮬레이터를 콜드 부트한 뒤 새 APK를 설치해 훈련·평가·결과·온보딩 화면을 눈으로 확인한다.
  시안과 구조가 가장 많이 달라진 곳부터 볼 것: **2칸으로 나뉜 파형 카드**, **세그먼트 모드 탭**,
  **등폭 정보 알약 3개**, **재생 버튼의 비활성 색**.
- 역치가 산출되는 세션(방향 전환 4회 이상)을 한 번 만들어 역치 추이 그래프 본체를 확인한다.
- 시안의 평가 화면(#3)은 진행 중 상태만 그려져 있다. 세션 시작 전에도 평가 배너를 띄우도록
  했는데(문구는 "평가 모드 · 정답은 종료 후 공개"로 분기), 실제로 보고 판단할 것.
- `app.json`의 `userInterfaceStyle`을 바꿨으므로, 릴리스 빌드 전에 prebuild가 한 번 돌아야
  네이티브 쪽에 반영된다.

## 성능

런타임 영향 없음. 색·간격 값 교체와 뷰 구조 정리뿐이고, 새로 도는 계산이나 추가 렌더 경로는 없다.
`SkiaWaveVisualizer`는 캔버스 하나(폭 = 화면폭)에서 작은 캔버스 둘(각 71dp)로 줄어 오히려
그리는 면적이 작아졌다. Feather 아이콘은 폰트 글리프라 이모지 텍스트와 비용이 비슷하다.

## 바꾸지 않은 것

- 오디오·스테어케이스·세션 로직 전부. `AudioEngine`, `StaircaseEngine`, `SessionManager`,
  저장소는 손대지 않았다.
- `trainingFlow.ts`의 상태 머신 규칙. 문구에서 이모지만 뺐고 분기는 그대로다
  (테스트 131개가 이를 확인한다).
- 화면에 쓰인 문구. 시안이 "텍스트는 원본 코드 그대로 유지했다"고 밝힌 대로,
  아이콘으로 대체된 이모지 외에는 문장을 바꾸지 않았다.
- 접근성 속성(`accessibilityRole`·`accessibilityLabel`·`accessibilityHint`·
  `accessibilityState`)과 최소 터치 타깃 48dp.
