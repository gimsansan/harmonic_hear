# 3단계 — 경험 개선

## ① 첫 실행 볼륨 맞추기 (P2-1) — 신규 `app/onboarding.tsx`

**왜.** 훈련 실패의 상당수는 실력이 아니라 "소리가 작아서"입니다.
지금까지는 홈에서 바로 훈련으로 들어가 **볼륨 문제인지 실력인지 구분할 수 없었습니다.**

**무엇을.** 3단계 안내 한 화면 — 이어폰 착용 / 기준음 4회 반복 재생하며 볼륨 조절 / 첫 문제는 쉽다는 안내.
첫 실행에만 뜨고, 설정에서 다시 볼 수 있습니다.

> **비유.** 시력검사 전에 안경을 닦는 것과 같습니다.
> 안경이 뿌연 상태로 잰 시력은 그 사람의 시력이 아닙니다.

## ② 세션 결과 화면 (P2-2) — 신규 `app/result.tsx`

**왜.** 기존에는 시스템 팝업으로 `시행 5회 / 정답률 60% / …` 한 줄만 띄우고 끝이었습니다.
정보 전달도 동기부여도 약했습니다.

**무엇을.** 전용 화면으로 분리하고 **직전 세션 대비 변화**를 가장 크게 보여줍니다.
역치 대형 표시 → `지난번보다 12 좋아졌습니다` → 시행·정답률·반응시간 → 난이도 궤적.

역치가 안 나온 세션은 `—`와 함께 **왜 안 나왔는지**(방향 전환 n회, 4회부터 산출)를 표시합니다.

## ③ 역치 추이 그래프 (P2-3) — 신규 `src/components/ThresholdChart.tsx`

**왜.** 통계 화면에 숫자 타일과 목록뿐이었습니다.
훈련 앱에서 사람을 계속 오게 만드는 건 **"내가 늘고 있다"는 시각적 증거**입니다.

**무엇을.** Skia 선그래프. 추가 라이브러리 없이 이미 있는 것으로 그렸습니다.

> **설계 판단 하나.** cent는 **낮을수록 좋습니다.** 그대로 그리면 실력이 늘수록 선이 내려가
> 직관과 반대로 읽힙니다. **y축을 뒤집어** 좋아질수록 선이 올라가게 했습니다.
> 그래프 아래에 그 사실을 명시했습니다.

## ④ 진동 피드백 (P4-5) — 신규 `src/utils/haptics.ts`

**왜.** `expo-haptics`가 설치돼 있는데 **호출이 0건**이었습니다.
청각 보조 기기 사용자 대상 앱에서 촉각 피드백은 특히 가치가 큽니다.

**무엇을.** 정답=Success / 오답=Error / 평가 모드=중립 탭.
설정에서 끌 수 있고, 꺼져 있으면 아무 일도 하지 않습니다.
햅틱 미지원 기기에서 앱이 죽지 않도록 예외를 삼킵니다.

> **평가 모드 주의.** 평가에서 정답/오답 진동을 주면 **정답을 숨긴 의미가 사라집니다.**
> 평가에서는 "접수됨"을 뜻하는 중립 진동만 줍니다.

## ⑤ 접근성 (P4-1 · P4-2)

**왜.** 전 코드에서 `accessibilityLabel` 사용이 **0건**이었습니다.
터치 타깃도 Android 최소 48dp에 못 미쳤습니다 (뒤로가기 26dp, 모드 버튼 34dp).

**무엇을.**
- 모든 주요 버튼에 `accessibilityRole` / `Label` / `State`
- 이모지는 스크린리더에서 숨기고(`accessibilityElementsHidden`), 읽기용 문구를 따로 둠
  (`PLAY_BUTTON_A11Y_LABEL` — 화면엔 `🔁 다시 듣기`, 읽을 땐 `같은 문제 다시 듣기`)
- `MIN_TOUCH_TARGET = 48` 토큰 도입, 버튼에 `minHeight` + 작은 버튼에 `hitSlop`

## ⑥ 색상 대비 (P3-3)

**왜.** `textDisabled(#6B70A0)`가 대비 **3.9:1로 WCAG AA 미달**인데,
하필 **"본 앱은 의료기기가 아닙니다" 규제 고지문**에 11px로 쓰이고 있었습니다.

**무엇을.** `#7B80A0`(4.75:1)으로 상향. `textMinimal`은 2.3:1이라
"본문에 쓰지 말 것"을 주석에 명시했습니다.

## ⑦ 파형 시각화 재작성 (P3-4 · P3-5 · P3-6 · P5-1)

한 파일에서 제안서 4건을 동시에 해결했습니다.

| 문제 | 수정 |
|---|---|
| A가 울릴 때 B 막대도 같이 움직임 | 애니메이션 값을 A/B 각각으로 분리 |
| 캔버스가 244px 고정 | `useWindowDimensions`로 화면 폭에 맞춤 |
| B 주파수가 답한 뒤에도 `? Hz` | 정답 공개 시 실제 값 표시 (평가 모드는 계속 숨김) |
| `useDerivedValue`를 `.map()` 안에서 호출 | `WaveBar` 컴포넌트로 추출 → 훅이 최상위로 |

> **훅 규칙 위반이 왜 문제였나.** 배열 길이가 상수라 지금은 돌아갔지만,
> 막대 개수를 바꾸는 순간 깨집니다. **"언젠가 터지는" 코드**였습니다.

## ⑨ 저장소 개선 (P5-4 · P5-5)

**왜.** `saveSession`이 실패를 `console.error`로 삼키고 정상 반환해서,
저장이 안 됐는데도 **"세션 완료"가 떴습니다.**
또 세션이 무제한으로 쌓여 단일 키가 수 MB까지 커질 수 있었습니다.

**무엇을.**
- `saveSession`이 `boolean`을 반환 → 실패 시 사용자에게 명확히 알림
- 최근 **200세션**까지만 보관, 오래된 것부터 폐기

## ⑩ 릴리스 설정 (P6)

| 항목 | 처리 |
|---|---|
| `name: "청능 애플리케이션"` | → **`"하모니튠"`**. "청능"은 청능재활을 연상시키는 임상 용어로, 명세서 §1 규제 방어 용어 가이드와 충돌했습니다 |
| `orientation: "default"` | → `"portrait"`. 레이아웃이 세로 전제 |
| `userInterfaceStyle: "automatic"` | → `"dark"`. 실제로 다크 전용이라 표기를 맞춤 |
| 버전 문자열 하드코딩 | `expo-constants`로 실제 값 읽기 |

## ⑪ 기타

- `COLORS.onPrimary` 토큰 도입 — `'#0A101D'` 하드코딩 제거
- 설정 화면의 "기본 오디오 모드" **장식용 배지**(눌러도 아무 일 없음)를
  → "볼륨 맞추기 안내 다시 보기"라는 **실제 동작**으로 교체
- 홈 메인 카드에 시안 테두리 — 서브 카드와 시각적 위계 구분
