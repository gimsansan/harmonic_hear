## 1. 실패해도 사용자가 못 보는 곳 (조용한 실패)

심각한 것부터 적습니다.

### (1) 결과 화면이 "불러오는 중"에서 멈출 수 있음

```
{저장소} !읽기 실패! --잡음(TrainingStorage.ts:79)--> [] 반환
    --> all.length === 0 --> return
    --> (session) = null 그대로
    --> [결과: "결과를 불러오는 중..." 영구]
```

`app/result.tsx:48`:

```js
if (cancelled || all.length === 0) return;
```

여기서 빠져나오면 `session`이 `null`로 남고, `:70-78`의 "결과를 불러오는 중..." 화면이 계속 나옵니다.

그 화면에는 **버튼이 하나도 없습니다.** 다시 시도할 길도, 홈으로 갈 길도 없습니다. 기기의 뒤로 가기를 눌러야 나갈 수 있는데, 이 화면에는 `replace`로 들어오므로(`training.tsx:230`) 뒤로 갈 곳도 애매합니다.

**읽기가 실패해서 `[]`가 온 경우와, 기록이 정말 0건인 경우가 같은 화면으로 처리됩니다.** `ask-error-handling.md`가 말하는 **영원한 로딩**에 해당합니다.

### (2) 소리가 안 나도 사용자는 아무 말을 못 들음

```
!AudioContext 시작 실패! --잡음--> console.warn --> 화면 변화 없음
```

`app/training.tsx:284-288`:

```js
const audioReady = await audioEngine.ensureRunning();
if (!audioReady) {
  console.warn('[Training] AudioContext를 시작할 수 없습니다.');
  return;
}
```

`:312-316`에도 같은 코드가 있습니다.

화면은 그대로 [대기]에 머무릅니다. **사용자 눈에는 버튼을 눌렀는데 아무 일도 안 일어나는 것**으로 보입니다. 소리를 못 듣는 것이 이 앱의 핵심 기능이 멈춘 상태인데, 그 사실이 화면에 전혀 안 나옵니다.

`AudioEngine` 쪽도 같습니다 — `console.warn` 후 `false`를 돌려줍니다 (`AudioEngine.ts:58`, `:63`, `:71`). 다만 이쪽은 **`false`를 돌려주므로 부르는 쪽이 알 수는 있습니다.** 알고도 표시를 안 하는 것은 화면 쪽 선택입니다.

### (3) 볼륨 안내에서 소리 예약 실패

`app/onboarding.tsx:64-67`:

```js
const ok = await audioEngine.playSequence(tones, 'wave');
if (!ok) { setIsPlaying(false); return; }
```

버튼이 원래대로 돌아올 뿐, 왜 소리가 안 났는지는 안 알려 줍니다.

**다만 로딩은 확실히 꺼집니다** — "재생 중… 볼륨을 조절하세요"에 갇히지는 않습니다. `ask-error-handling.md`의 "영원한 로딩"은 피했습니다.

### (4) 통계 읽기 실패

`app/stats.tsx:63-67`:

```js
} catch (e) {
  console.error('Failed to load stats:', e);
} finally {
  setRefreshing(false);
}
```

`stats`가 `null`로 남아 타일이 전부 `-`로 보입니다. "못 읽었다"와 "기록이 없다"가 구분되지 않습니다.

**로딩은 `finally`에서 확실히 꺼집니다.** 당겨서 새로고침이 도는 채로 멈추지는 않습니다.

### (5) 설정 저장 실패해도 화면은 성공처럼 보임

`AppSettingsStorage`의 쓰기 3개가 실패 시 `console.error`만 합니다 (`:57`, `:75`, `:92`).

부르는 쪽은 실패인지 **알 방법이 없습니다** — 돌려주는 값이 `Promise<void>`이기 때문입니다.

`app/settings.tsx:69-72`를 보면 화면을 먼저 바꾸고 저장을 나중에 합니다:

```js
setReferencePreset(preset);                                  // 화면 먼저
await AppSettingsStorage.setReferencePitchPreset(preset);    // 저장 나중
```

프리셋을 골랐는데 저장이 실패하면, 그 화면에서는 "선택됨" 뱃지가 붙어 있지만 훈련 화면에 들어가면 예전 값으로 돌아갑니다.

### (6) 데이터 초기화 실패해도 "완료" 팝업이 뜸

`app/settings.tsx:84-85`:

```js
await TrainingStorage.clearAll();
Alert.alert('완료', '모든 훈련 데이터가 초기화되었습니다.');
```

`clearAll()`은 실패해도 예외를 밖으로 던지지 않고 `console.error`만 합니다 (`TrainingStorage.ts:120-122`). **지워지지 않았어도 "완료"가 뜹니다.**

## 2. 실패를 제대로 다룬 곳

### 세션 저장 실패 — 이 앱에서 실패를 알리는 유일한 경로

```
{저장소} !쓰기 실패! --잡음(TrainingStorage.ts:65)--> false 반환
    --> [훈련: 저장 실패 팝업] + 화면 이동 안 함
```

`TrainingStorage.saveSession`은 다른 함수들과 달리 **성공/실패를 `boolean`으로 돌려줍니다.** 주석에도 적혀 있습니다 (`:29-30`):

> 저장에 성공했는지. 실패를 성공처럼 보이게 하면 안 되므로 호출부에서 반드시 확인하십시오. (P5-5)

부르는 쪽도 실제로 확인합니다 (`training.tsx:218-227`). 팝업 문구가 특히 좋습니다:

> 기록을 저장하지 못했습니다. 기기 저장 공간을 확인해 주세요.
> **이번 세션 결과는 통계에 반영되지 않습니다.**

무엇이 실패했는지, 무엇을 하면 되는지, **그래서 어떻게 되는지**까지 세 가지를 다 말합니다. 기술 메시지를 그대로 보여 주지 않습니다.

그리고 **화면을 안 옮깁니다.** 결과 화면으로 넘어가면 저장 안 된 세션이 저장된 것처럼 보이기 때문입니다.

### 진동 실패 — 일부러 삼킵니다

`src/utils/haptics.ts:23-28`:

```js
function safe(run: () => Promise<unknown>): void {
  if (!enabled) return;
  run().catch(() => {
    // 햅틱 미지원 기기 등 — 무시
  });
}
```

빈 `catch`지만 **이유가 주석에 적혀 있습니다.** 파일 머리말(`:7`)에도 "실패해도 앱 동작에 영향이 없어야 하므로 모든 호출은 예외를 삼킵니다"라고 명시했습니다.

진동이 안 되는 것이 앱을 막을 이유가 없으므로 타당한 선택입니다. `ask-error-handling.md`가 경계하는 "삼킨 에러"는 **이유 없이 삼키는 것**이고, 여기는 이유가 적혀 있습니다.

### 설정 읽기 실패 — 기본값으로 대체

| 무엇 | 실패 시 | 왜 그 쪽이 안전한가 |
|---|---|---|
| 기준음 프리셋 | `'standard'` (440Hz) | 가장 흔한 기준음 |
| 진동 | 켜짐 | 켜져 있다 안 울리는 편이 나음 |
| 온보딩 완료 | `false` (안 봤음) | 안내를 한 번 더 보여 주는 쪽이 안전 |

`AppSettingsStorage.ts:39-42`, `:67`, `:84`.

## 4. 앱 전체를 받치는 그물이 없음

**에러 경계(Error Boundary)가 어디에도 없습니다.** `_layout.tsx`에도 없습니다.

에러 경계는 화면을 그리다 터졌을 때 앱 전체가 멈추는 대신 대체 화면을 보여 주는 장치입니다. 없으면 그리는 도중 예외가 나는 순간 앱이 멈춥니다.

터질 만한 자리를 찾아보면:

| 어디 | 무엇 |
|---|---|
| `TrainingStorage.ts:78` | 저장된 글자가 깨졌으면 `JSON.parse`에서 터짐 — 이건 `try`로 감싸여 있음 |
| `stats.tsx:198` | `session.totalTrials`가 0이면 `NaN%`가 그려짐 (터지진 않음) |
| `result.tsx:93` | `session.trials`가 없으면 터짐 — 옛날 버전 세션에 이 필드가 없을 경우 |

세 번째는 `SessionResult`의 `trials`가 물음표 없는 필수 필드라 지금은 항상 있다고 보지만, 저장된 값을 실제로 검사하지 않으므로 보장은 아닙니다(→ [#5 타입·계약](./파악_5_타입계약_2026-08-21.md)).
