### 에뮬레이터 확인으로 정리된 것

동작·로직 항목은 에뮬레이터에서도 실기기와 동일하게 재현되므로 유효한 확인입니다.

- B. 답변 중복 제출 차단
- C. 다시 듣기 / 다음 문제 분기
- D. 반응 시간
- E. 화면 배선 (버튼 활성 타이밍)

### 에뮬레이터로 **정리되지 않은** 것 ⚠️

**A. 소리 항목은 여전히 미확인입니다.**

에뮬레이터의 오디오는 호스트 PC의 오디오 스택을 거치며 리샘플링·버퍼링이 추가로 일어납니다.
그 과정에서 다음이 실기기와 다르게 나타납니다.

| 항목 | 에뮬레이터에서 왜 못 믿나 |
|------|------------------------|
| 톤 지속 길이 (A-1) | 버퍼링으로 체감 길이가 달라질 수 있음 |
| **끝단 클릭/팝 잡음 (A-2)** | 호스트 오디오 스택이 **가려버리는 경우가 많음.** 에뮬레이터에서 안 들려도 실기기에서 날 수 있음 |
| 저역(262Hz) 재생 (A-4) | 저주파일수록 차이가 큼 |

> **결론: A 항목은 실기기 + 이어폰으로 다시 확인해야 합니다.**
> 특히 A-2(잡음)는 이번 수정이 새로 유발했을 수 있는 위험이라 남겨 두면 안 됩니다.

## 왜 필요한가

자동 테스트 86개가 통과했지만, **테스트가 닿지 못한 영역이 두 곳** 있습니다.

| 영역 | 왜 자동 테스트로 못 하나 |
|------|------------------------|
| **실제 소리** | 오디오 스케줄(예약된 숫자)만 검증했습니다. 그 숫자대로 들리는지는 귀로만 확인됩니다 |
| **화면 배선** | 타이머가 제때 도는지, 버튼이 정확한 순간에 켜지는지는 컴포넌트 테스트가 필요한데 아직 없습니다 |

특히 **P0-4는 새 위험을 만들었을 수 있습니다.** 서스테인 앵커를 넣으면서
소리 끝에서 "딸깍/툭" 잡음이 생길 가능성이 있는데, 이건 들어봐야만 압니다.

## A. 소리 확인 (P0-4) — 가장 중요

> 이 항목이 유일하게 **사람만 확인 가능**합니다.

### A-1. 소리가 1초 동안 지속되는가

1. 훈련 → **소리 듣기** 누르기
2. 첫 번째 소리(A)에 집중

| | 확인 |
|---|---|
| ✅ 정상 | "삐———" 하고 **1초 정도 이어짐**. 소리 크기가 중간에 확 줄지 않음 |
| ❌ 실패 | "삑" 하고 **짧게 사라짐**. 시작만 들리고 금방 작아짐 |

> 수정 전에는 소리가 시작하자마자 계속 작아져서 체감 길이가 수백 ms였습니다.
> 지금은 켜짐(0.05초) → **유지(0.9초)** → 꺼짐(0.05초) 구조여야 합니다.

### A-2. 시작·끝에 잡음이 없는가 ⚠️ 새로 생겼을 수 있는 문제

같은 소리를 여러 번 들으면서 **소리가 끝나는 순간**에 집중하세요.

| | 확인 |
|---|---|
| ✅ 정상 | 부드럽게 사라짐 |
| ❌ 실패 | 끝날 때 **"딱" / "툭" / "지직"** 하는 짧은 잡음 |

> 이번 수정에서 Release 시작점에 값을 고정하는 코드를 넣었습니다.
> 이론상 클릭 방지는 유지되지만, 기기에 따라 다르게 나올 수 있어 확인이 필요합니다.
> **잡음이 들리면 알려주세요. Release 시간을 늘리는 등으로 조정합니다.**

### A-3. 두 모드 모두

- [ ] **🌊 순수 파형 (DSP)** — A-1, A-2 확인
- [ ] **🎤 사람 목소리("아~")** — A-1, A-2 확인

> 목소리 모드는 원래 음색이 로봇 같습니다. 그건 정상입니다.
> 여기서 볼 것은 **길이와 잡음**뿐입니다.

### A-4. 기준음 3개 모두

설정 → 기준 음고를 바꿔가며 확인하세요. 낮은 음일수록 잡음이 잘 들립니다.

- [ ] 표준 (440 Hz)
- [ ] 중역 (330 Hz)
- [ ] 저역 (262 Hz)

## B. 답변 중복 제출 차단 (P0-1)

1. **소리 듣기** → A, B 다 듣기
2. **높음** 또는 **낮음** 아무거나 누르기
3. 피드백 카드가 뜬 것을 확인
4. **같은 버튼을 5~6번 더 눌러보기**

| | 확인 |
|---|---|
| ✅ 정상 | 버튼이 **흐려져 있고**(비활성) 눌러도 반응 없음. 화면의 `시행 n회`가 **안 올라감** |
| ❌ 실패 | 버튼이 눌리고 시행 수·정답률이 계속 바뀜 |

- [ ] 확인 완료

## C. 다시 듣기가 문제를 바꾸지 않는가 (P0-2)

### C-1. 버튼 문구가 상황에 따라 바뀌는가

| 상황 | 나와야 할 문구 |
|------|---------------|
| 훈련 시작 전 | ▶️ 소리 듣기 (A → B) |
| 재생 중 | 🔊 소리 감상 중... |
| **재생 끝, 아직 답 안 함** | **🔁 다시 듣기 (A → B)** |
| 답한 뒤 | ▶️ 다음 소리 듣기 (A → B) |

- [ ] 네 가지 다 확인

### C-2. 같은 문제가 나오는가

1. **소리 듣기** → 끝까지 듣기
2. 답하지 말고 **🔁 다시 듣기**를 3~4번 누르기
3. 매번 A와 B의 높낮이 관계에 집중

| | 확인 |
|---|---|
| ✅ 정상 | 매번 **같은 소리**. B가 높으면 계속 높고, 낮으면 계속 낮음 |
| ❌ 실패 | 들을 때마다 방향이 달라짐 |

> 차이가 작아서 헷갈리면 설정에서 **저역(262Hz)** 으로 바꾸고,
> 일부러 몇 번 틀려서 음정 차이를 100 이상으로 키운 뒤 확인하면 쉽습니다.

- [ ] 확인 완료

### C-3. 답한 뒤에는 새 문제가 나오는가

1. 답하기
2. **▶️ 다음 소리 듣기** 누르기
3. 이걸 10번쯤 반복

| | 확인 |
|---|---|
| ✅ 정상 | 높음/낮음이 **뒤섞여** 나옴 |
| ❌ 실패 | 계속 한쪽만 나옴 |

- [ ] 확인 완료

## D. 반응 시간이 정상 범위인가 (P0-3)

1. 훈련을 **5회 이상** 진행 (평소 속도로 답하기)
2. **세션 종료 및 저장**
3. 홈 → **훈련 통계** → **평균 반응 시간**

| | 확인 |
|---|---|
| ✅ 정상 | 대략 **500~2500ms** |
| ❌ 실패 | **3000ms 이상** (수정 전 증상 — 재생 시간 2.5초가 섞여 있음) |

### D-1. 빠르게 답해보기

소리가 끝나자마자 바로 누르는 세션을 하나 더 해보세요.

| | 확인 |
|---|---|
| ✅ 정상 | **500ms 이하**도 나옴 |
| ❌ 실패 | 아무리 빨라도 3000ms 밑으로 안 내려감 |

- [ ] 확인 완료

> ⚠️ 기존 기록이 남아 있으면 평균이 섞입니다.
> 정확히 보려면 **설정 → 훈련 데이터 전체 초기화** 후 측정하세요. (아래 F 참고)

| | 확인 |
|---|---|

| ❌ 실패 | 소리 재생 중에 이미 눌리거나, 끝난 뒤 한참 있다가 켜짐 |

- [ ] 확인 완료

### E-2. 다시 듣기 후에도 정상인가

1. 재생 끝 → **다시 듣기** → 재생 끝
2. 답변 버튼이 다시 켜지는지
3. 답이 정상적으로 채점되는지

- [ ] 확인 완료

### E-3. 파형 그래프

| | 확인 |
|---|---|
| 참고 | A 소리 때 왼쪽이 **시안색**, B 소리 때 오른쪽이 **주황색**으로 켜짐 |

| | 확인 |
|---|---|
| ✅ 정상 | `200 → 200 → 150 → 150 → 100` (2문항마다 50씩) |
| ❌ 실패 | 10씩만 줄어듦 |

- [ ] 확인 완료

| | 확인 |

> 화면 아래 `난이도 방향 전환 2/4` 진행 표시도 함께 보세요.

## K. 재빌드 필요 (사용자 실행)

```
rive-react-native            네이티브 런타임 포함, 호출 0건
react-native-svg             호출 0건
react-native-svg-transformer 연결 안 됨
expo-updates                 설정 없이 설치만
```

반영하려면:

```bash
npm install
npx expo run:android
```
