HarmoniTune(하모니튠)은 두 소리의 높낮이 차이를 구별하는 **음고 감각 훈련 Expo(React Native) 앱**이에요. 요청하신 범위(`app`, `src`)의 폴더·파일 역할을 전체 동작 흐름과 함께 정리했습니다.

---

## 전체 동작 한눈에

```
홈(index) → [첫 실행] 온보딩(볼륨 맞추기) → 훈련(training) → 결과(result) → 통계(stats) / 설정(settings)
```

화면(`app/`)이 사용자와 만나고, 실제 두뇌(`src/`)가 소리 합성·난이도 계산·저장을 담당하는 구조입니다. 화면은 "무엇을 보여줄지"만 알고, "어떻게 계산할지"는 전부 `src`에 위임해요.

---

## `app/` — 화면(라우팅)

Expo Router 기반이라 **파일 하나 = 화면 하나 = URL 하나**입니다.

- `_layout.tsx` : 모든 화면을 감싸는 최상위 뼈대. 다크 배경, 상태바, 화면 전환 애니메이션 설정.
- `index.tsx` : **홈**. 훈련/통계/설정 진입 카드. 첫 실행이면 온보딩으로, 아니면 바로 훈련으로 분기.
- `onboarding.tsx` : **첫 실행 볼륨 맞추기 안내**. 기준음을 4번 들려주며 볼륨을 맞추게 함. 실력이 아니라 소리가 작아서 틀리는 걸 막는 화면. (딱 한 번만 노출)
- `training.tsx` : **핵심 훈련 화면**. `소리 A(기준) → 0.5초 대기 → 소리 B(비교) → 답변 대기` 흐름을 지휘. 훈련/평가 모드 전환, 앱 이탈 시 라운드 폐기, 세션 시작·종료·저장까지 조율하는 가장 큰 파일.
- `result.tsx` : **세션 결과**. 대표 지표인 변별 역치, 직전 세션 대비 향상도, 난이도 궤적을 보여줌.
- `stats.tsx` : **누적 통계**. 최고/최근 역치, 정답률, 반응 시간, 최근 10세션, 역치 추이 그래프.
- `settings.tsx` : **설정·정보**. 기준 음고 프리셋(표준/중역/저역), 진동 on/off, 온보딩 다시 보기, 데이터 초기화, 앱 고지 문구.

## `src/` — 앱의 두뇌(로직)

### `src/constants/`
- `theme.ts` : **모든 상수의 중앙 저장소**. 색상·간격·폰트 같은 디자인 토큰뿐 아니라, `AUDIO`(재생 시간·주파수 한도), `STAIRCASE`(난이도 규칙), `ASSESSMENT`(평가 종료 조건), `REFERENCE_PRESETS`(기준음)까지. 이 파일만 바꾸면 앱 전체 동작이 조정됨.

### `src/audio/` — 소리
- `AudioEngine.ts` : **소리를 실제로 만드는 신디사이저**. Web Audio API로 순수 파형(sine)과 사람 목소리 "아~"(포먼트 합성)를 생성. 핵심은 `playSequence` — A와 B 두 톤을 **하나의 오디오 시계 기준점에 한 번에 예약**해서, 안드로이드에서 JS가 버벅여도 A→B 간격이 흔들리지 않게 함(간격이 흔들리면 음고 대신 '시간 단서'가 되어버림).
- `pitchUtils.ts` : **음고 계산기(순수 함수)**. Hz↔cent 변환, 재생 길이 보정, 주파수를 가청/허용 범위로 자르는(clamp) 함수들.
- `__tests__/AudioEngine.test.ts`, `__tests__/pitchUtils.test.ts` : 위 두 파일의 동작을 고정하는 검증 테스트.

### `src/training/` — 훈련 규칙(가장 중요한 폴더)
- `StaircaseEngine.ts` : **난이도 조절 엔진**. 정신물리학의 표준 기법인 **2-down-1-up 계단법**. 연속 2회 정답이면 음정 차이를 줄이고(어려워짐), 틀리면 늘림(쉬워짐). 난이도가 방향을 바꾸는 지점("반전")들의 평균으로 **변별 역치**를 산출. 이게 앱의 대표 성과 지표.
- `SessionManager.ts` : **한 세션의 진행 관리자**. StaircaseEngine을 감싸서 라운드 준비, 반응 시간 측정, '다시 듣기' 횟수 기록, 앱 이탈 시 라운드 폐기, 평가 모드 자동 종료 판정, 세션 결과 묶기를 담당. (현재 열려 있는 파일)
- `trainingFlow.ts` : **화면 상태 머신 규칙(순수 함수 모음)**. `idle→playing→waiting→answered` 전이 규칙을 화면에서 떼어냄. "답변은 한 라운드에 한 번만", "waiting에서만 다시 듣기", "평가 모드는 정답 숨김" 같은 **측정 신뢰도 규칙**을 한 곳에서 관리.
- `__tests__/` : `StaircaseEngine.test.ts`, `SessionManager.test.ts`, `trainingFlow.test.ts` — 이 세 규칙 파일이 나중에 깨지지 않도록 잠가두는 회귀 테스트. 폴더가 복잡해 보이는 이유가 바로 이 로직들이 **측정값의 정확성과 직결**돼서 별도 파일 + 테스트로 엄격히 분리했기 때문이에요.

### `src/components/` — 재사용 UI 조각
- `ModeTab.tsx` : 순수 파형 / 사람 목소리 모드 전환 탭.
- `AnswerButtons.tsx` : "B가 더 높음 / 낮음" 답변 버튼.
- `SkiaWaveVisualizer.tsx` : A/B 소리를 GPU(Skia)로 그리는 파형 애니메이션. 재생 중인 소리를 시각적으로 강조.
- `FeedbackCard.tsx` : 정답/오답 피드백 카드(페이드+슬라이드 애니메이션).
- `ThresholdChart.tsx` : 통계 화면의 역치 추이 선그래프(위로 갈수록 좋아지게 y축 반전).

### `src/storage/` — 저장(오프라인, AsyncStorage)
- `TrainingStorage.ts` : **세션 기록 저장소**. 세션 저장/조회, 최고 기록 갱신, 통계 집계. 무한히 쌓이지 않게 최대 200세션만 보관.
- `AppSettingsStorage.ts` : **설정 저장소**. 기준음 프리셋, 진동 on/off, 온보딩 완료 여부만 따로 관리.

### `src/utils/`
- `haptics.ts` : **진동 피드백**. 청각 보조 기기 사용자를 위해 정답/오답을 진동으로도 알림. 설정에서 끄면 아무 것도 안 하고, 실패해도 앱에 영향 없게 예외를 삼킴.

## 루트 설정(참고)
- `app.json` : Expo 앱 이름(HarmoniTune), 안드로이드 패키지, 아이콘/스플래시, 플러그인 설정.
- `package.json` : 의존성·스크립트. 테스트는 `jest-expo/android` 프리셋(안드로이드 기준)으로 돌아감.

---

핵심만 요약하면: **`app`=보여주기, `src/training`=훈련의 두뇌, `src/audio`=소리, `src/storage`=기록, `src/components`=UI 조각, `constants/theme.ts`=모든 규칙의 다이얼**입니다.

특정 폴더(예: `src/training`)를 **한 줄 한 줄 코드 분석**으로 더 깊게 보고 싶으시면 말씀해 주세요.
