# Cent 개념 활용과 시작 간격(50)에 대한 정리

이 문서는 Harmonic Hear에서 **cent**가 어디에 쓰이는지, 시작 간격 **50 cent**를 어떻게 봐야 하는지, 그리고 그렇게 정한 이유를 앱·청능 관점에서 정리한 것입니다.

---

## 1. Cent란 무엇인가 (앱에서의 의미)

- **Hz**: 소리의 절대 주파수(초당 진동 횟수). 예: 기준음 A4 = **440 Hz**.
- **cent**: 두 음의 **상대 간격**을 로그 스케일로 잰 단위.  
  한 옥타브 = 1200 cent, 반음(100 cent)의 1/100이 1 cent.

앱은 “B가 몇 Hz인가”를 사용자에게 묻지 않습니다.  
**A와 B의 높이 차이(음정 격차)**를 cent로 관리하고, 재생할 때만 Hz로 바꿉니다.

변환식 (`src/audio/pitchUtils.ts`):

```text
f = baseHz × 2^(cents / 1200)
```

예: 440 Hz + 50 cent ≈ **452.9 Hz**.

---

## 2. 이 앱에서 cent를 어떻게 적용하는가

### 2.1 난이도 엔진의 핵심 단위

`StaircaseEngine` (`src/training/StaircaseEngine.ts`)이 관리하는 상태:

| 필드 | 의미 |
|------|------|
| `centsDifference` | 현재 A–B 음정 격차 (난이도) |
| `baseFreq` | 기준 주파수 (기본 440 Hz) |
| `targetFreq` | B에 쓸 실제 Hz (`centsToFreq` 결과) |
| `isHigher` | 이번 라운드에서 B가 더 높은지 |

매 라운드 (`prepareRound`):

1. 방향(높음/낮음)을 랜덤 결정
2. `±centsDifference`를 기준음에 적용해 `targetFreq` 계산
3. `AudioEngine`이 A=`baseFreq`, B=`targetFreq`로 재생

즉 cent는 **“얼마나 미세하게 구분해야 하는가”**의 조작 변수이고, Hz는 **스피커로 나가는 자극**입니다.

### 2.2 적응형 계단법 (값이 변하는 방식)

상수 (`src/constants/theme.ts` → `STAIRCASE`):

| 항목 | 값 | 의미 |
|------|-----|------|
| `INITIAL_CENTS` | 50 | 세션 시작 격차 |
| `MIN_CENTS` | 10 | 가장 어려운 단계 |
| `MAX_CENTS` | 300 | 가장 쉬운 단계 (문헌 프록시 잠정값 · 파일럿 검증 대상) |
| `STEP_DOWN` / `STEP_UP` | 10 | 정답(연속 2회)/오답 시 조정 |
| `STREAK_THRESHOLD` | 2 | 연속 2회 정답일 때만 격차 감소 |

규칙 요약:

- 격차 **큼** → 구분 쉬움  
- 격차 **작음** → 구분 어려움  
- 연속 2회 정답 → −10 (더 어렵게)  
- 오답 → 바로 +10 (조금 쉽게)

피드백 문구의 “음정차이 N”도 이 `centsDifference`입니다. 사용자는 내부 단위 이름을 몰라도, 화면의 **음정 차이** 숫자로 난이도를 체감합니다.

### 2.3 그 밖의 cent 사용처

| 영역 | 역할 |
|------|------|
| UI (`training.tsx`) | 배지·상태 표시: `음정 차이: {centsDifference}` |
| 세션/통계 | 문항별 격차, 세션 내 **최소 달성 cent**(최고 난이도 기록) |
| 키존/샘플 (`keyzoneUtils`, `KEYZONE`) | 샘플 간격 200 cent, detune 상한 ±100 cent — **자극 생성 품질**용 (난이도 계단과는 별 레이어) |
| 시각화 (`SkiaWaveVisualizer`) | `440 Hz` / `? Hz`는 라벨 성격. 실제 라운드 `targetFreq`와 실시간 연동은 하지 않음 |

정리하면, 청능 루프의 중심은 **계단법의 `centsDifference` → Hz 변환 → 재생 → 높음/낮음 판정**입니다.

## 3. “시작 50 cent는 쉬운~중간이다”에 대한 생각

### 3.1 이전에 짧게 말한 판단의 맥락

“50 cent ≈ 반음의 절반 → 청능에서 쉬운~중간, 어렵다고 보기 어렵다”는 말은,  
**절대적 간격만** 놓고 보면 흔히 나오는 감각입니다.

- 100 cent = 인접 반음 한 칸 → 음악적으로 “다른 음”으로 느껴지기 쉽고  
- 50 cent는 그 절반 → “아주 미세한 JND(최소 가청 차이) 훈련”까지는 아닌,  
  **구분 가능한 편에 가까운 출발점**으로 읽히기 쉽습니다.

다만 이 말은 **대상·과제 조건**에 따라 달라집니다.

### 3.2 왜 “쉽다고만” 단정하면 부족한가

같은 50 cent라도 체감 난이도는 달라집니다.

- **청취 경험**: 음악 훈련·튜닝 경험이 있으면 50은 비교적 분명할 수 있음  
- **비숙련·일상 청취**: “거의 같다”고 느끼는 경우도 흔함  
- **과제 형태**: A→B 순차 비교, 짧은 톤, 방향(높/낮)만 고르기 → 동시 비교보다 부담이 다름  
- **자극 종류**: 순수 사인파 vs 포먼트/목소리 — 배음·음색이 단서를 주거나 가릴 수 있음  

정신물리학에서 말하는 주파수 JND는 조건에 따라 **수 cent대**까지도 논의됩니다.  
그 기준으로 보면 50은 “극한 난이도”는 아니지만,  
**앱이 노리는 ‘세밀한 듣기의 입구’로는 충분히 도전적인 쪽**에 가깝습니다.

### 3.3 수정된 한 줄 정리

> 50 cent는 “초보에게도 항상 쉬운 간격”이 아니라,  
> **반음의 절반이라 과하게 티 나진 않으면서도, 적응 계단으로 더 조이거나 벌릴 수 있는 중간 출발점**에 가깝다.

이전의 “쉬운~중간”은 **음악적 반음 스케일 대비**의 표현이고,  
이 앱의 제품 의도(아래 4절)와 맞추면 **“중간 출발 · 체감은 사람마다 다름”**이 더 정확합니다.

## 4. 앱 관점에서의 생각

### 4.1 제품이 50을 어떻게 설명하고 있는가

`docs/앱_사용법.md`는 시작 50을 이렇게 전제합니다.

- 반음의 절반 정도라 **차이가 크게 들리지 않는 것이 정상**
- “거의 안 나요” FAQ → **세밀한 듣기를 연습하는 구조**라고 안내
- 오답 시 +10으로 **조금 쉽게** 풀어 줌

즉 앱의 UX 메시지는 “처음이라 쉽게 들리게 했다”가 아니라,  
**“처음부터 세밀하게 듣게 하고, 못하면 계단이 완화한다”**에 가깝습니다.

### 4.2 왜 이 구조가 청능 앱에 맞는가

1. **사용자에게 cent를 가르치지 않음**  
   과제는 “B가 더 높/낮?”뿐. cent는 엔진·통계용 내부 자입니다.

2. **개인 문턱에 맞춤**  
   고정 50만 반복하면 어떤 이는 지루하고 어떤 이는 좌절합니다.  
   10~300 범위의 계단법이 그 간극을 메웁니다.

3. **로그 간격(cent)이 Hz 고정 스텝보다 자연스러움**  
   “항상 +10 Hz”는 저음/고음에서 체감이 달라집니다.  
   cent는 상대 음고 감각에 더 잘 맞는 표준 단위입니다.

4. **성과 지표가 명확함**  
   “정답률”과 함께 **도달한 최소 cent**가 “얼마나 미세하게 구분했는가”를 보여 줍니다.

### 4.3 UI의 440 Hz / ? Hz와의 관계

파형 아래 `440 Hz` / `? Hz`는 **기준 vs 비교**를 직관적으로 보여 주는 라벨입니다.  
실제 난이도·정답 판정의 숫자는 화면 배지의 **음정 차이(cent)** 쪽입니다.  
(시각화 컴포넌트는 현재 라운드의 `targetFreq`를 받아 표시하지는 않습니다.)

## 5. 시작 간격을 50으로 정한 이유 (코드·스펙 기준)

명시적으로 “심리실험 N명 결과로 50을 골랐다”는 문서는 없고,  
구현 스펙·사용법·상수 배치에서 읽히는 설계 의도는 다음과 같습니다.

### 5.1 반음 체계와의 정렬

- 반음 = 100 cent  
- 시작 = **50** = 반음의 절반  
- 스텝 = **10** → 50에서 10 단위로 내려가며 10까지 (또는 300까지)

음악·튜닝에서 익숙한 격자(100/반음) 위에 올려 둔 **절반 칸**이라,  
설명(“반음의 절반”)과 구현이 일치합니다.

### 5.2 계단 구간의 출발과 상한

범위가 **10 ~ 300**일 때:

- 너무 큰 시작(예: 300) → 초반이 지나치게 쉽고, “세밀한 듣기” 브랜드와 어긋남  
- 너무 작은 시작(예: 10~20) → 첫 세션부터 좌절·포기 위험  
- **50** → 쉽지 않은 입구 + 오답 시 위로(최대 300), 숙련 시 아래로(최소 10) 여유  

`앱_사용법.md`의 “차이가 크지 않은 것이 정상” 문구와 같은 방향입니다.  
상한을 150에서 300으로 올린 이유는 아래 §5.3을 참고합니다.

### 5.3 상한을 150 → 300으로 올린 이유

본훈련(wave, 순수 사인파)의 `MAX_CENTS`만 변경했습니다.  
시작 50·하한 10·스텝 10·2-down/1-up은 그대로입니다.

**배경**

- 목표 집단은 **경도~중등도 SNHL·고령**의 주파수/음고 변별(DLF)입니다.
- 검색 범위(웹·초록 중심)에서 **한국인 해당 집단의 DLF 규준(Hz/cent/반음)** 은 확인되지 않았습니다.  
  국내에 풍부한 것은 순음 역치(dBHL)·어음인지이지, DLF 규준이 아닙니다. dBHL로 DLF를 대체할 수 없습니다.
- 따라서 난이도 상한은 “국내 규준으로 확정”이 아니라, **인접 집단 문헌을 앵커로 한 잠정값 + 파일럿 자체 수집**으로 잡습니다.

**왜 300인가**

- 한국 인공와우(CI) 사용자 음악지각 연구의 음고 변별 DL(초록 기준, 전문 미확인):  
  기준 262 Hz에서 약 **2.7 ± 1.7 반음** ≈ **270 cent**대.
- 기존 상한 **150 cent(1.5 반음)** 는 이 프록시보다 좁아, 변별이 어려운 사용자가 계단 천장에 자주 걸릴 수 있습니다.
- 상한 **300 cent(3 반음)** 는 위 평균(≈270)에 소폭 여유를 둔 값입니다.  
  CI 집단 전체 분포(예: 다른 주파수에서 더 큰 역치)를 모두 덮는 값은 아닙니다.
- 목표 집단(경도~중등도)은 CI보다 변별이 나을 가능성이 커서, 파일럿 후 **상한을 다시 줄이는 것**도 가능합니다.

**지위 (중요)**

- 300은 **문헌 프록시 기반 잠정값**이며, 임의 확정값이 아닙니다.
- 앱 포지션은 **디지털 웰니스 / 비의료기기**입니다. 파일럿·국내 DLF 규준이 확보되면 재확인합니다.
- 검증 상태: CI 수치는 **초록 기준·원문 전문 미확인**. 인용·확정에는 원문 대조가 필요합니다.

**모드 역할 (같이 정한 전제)**

- **본훈련 = wave only**, 범위 10~300. 정밀 변별·역치 추적에 사용합니다.
- **voice/키존(실녹음)** 은 본역치용 상한을 300으로 잡지 않습니다.  
  키존의 ±100 cent는 “훈련 상한”이 아니라 **한 샘플당 피치 시프트 한도**이며, 목소리는 전이(실음성) 연습용으로 둡니다.
- 현행 voice 모드는 포먼트 합성 “아~”이며, 키존 실녹음과는 별개입니다.

**파일럿에서 볼 것**

- 실측 분포가 10~300 안에서 충분한지, 천장(300)·바닥(10)에 과도하게 몰리는지
- 고령·SNHL에서 시작값 50이 과도한 초기 실패를 낳는지 → **80~100 시작** 검토
- 가능하면 기준 주파수 440(앱 기본)과, CI 비교용 262 Hz 중 하나 이상을 맞춰 기록

### 5.4 연속 2-down / 1-up과의 궁합

연속 2회 정답에만 −10인 이유는, 우연 정답으로 난이도가 급락하는 것을 줄이기 위함입니다.  
시작이 50이면:

- 숙련: 50 → 40 → … → 10 으로 조여 감  
- 비숙련: 오답 시 60, 70… 으로 완화되어 **포기 전에 다시 성공 경험**을 줌  

초기값을 극단으로 두면 이 완충이 덜 효과적입니다.

### 5.5 스펙·프로토타입부터의 일관값

통합 구현명세서 프로토타입 UI도 초기 `useState(50)`, 피드백에 Cents를 쓰도록 잡혀 있었고,  
현재 `STAIRCASE.INITIAL_CENTS = 50`과 동일합니다.  
즉 후반에 임의로 끼워 넣은 값이 아니라, **음고정밀 훈련 + 적응 계단** 설계의 기본 출발점으로 유지된 값입니다.

## 6. 한눈에 보는 관계

```text
[난이도] centsDifference (예: 50)
        │
        ▼ centsToFreq(440, ±50)
[자극]  A = 440 Hz , B ≈ 452.9 Hz (또는 아래쪽)
        │
        ▼ 사용자: 높음 / 낮음
[적응]  연속 2정답 → −10 / 오답 → +10
        │
        ▼
[기록]  정답률, 최소 달성 cent
```

- **Cent** = 훈련 난이도·통계의 자  
- **Hz** = 실제로 재생되는 소리  
- **시작 50** = “티 나게 쉬운 워밍업”이 아니라, **세밀 듣기의 중간 출발점**  
- 이전의 “쉬운~중간” 표현은 반음 대비로는 가능하나,  
  **이 앱의 의도·안내문 기준으로는 ‘도전적이되 적응 가능한 시작’**으로 이해하는 편이 맞습니다.
