# HarmoniTune 개선 제안 — 쉬운 설명 버전

작성일: 2026-08-07

이 문서는 [`앱_개선_제안서.md`](./앱_개선_제안서.md)의 **쉬운 말 버전**입니다.
전문 용어와 코드 위치는 빼고, "무슨 일이 벌어지고 있고 왜 문제인지"만 담았습니다.

기술적인 근거·수정 방법·파일 위치가 필요하면 원본 문서를 봐주세요.

---

## 이 앱이 하는 일

"삐—" 소리 두 개를 차례로 들려주고 **두 번째가 더 높았나요, 낮았나요?** 를 맞히는 게임입니다.

- 맞히면 → 두 소리의 차이를 좁혀서 더 어렵게 만듭니다
- 틀리면 → 차이를 벌려서 쉽게 만듭니다

이걸 반복하면 "이 사람은 어느 정도 미세한 차이까지 구별하는가"라는 **개인의 한계선**을 찾을 수 있습니다.
그게 이 앱의 핵심 가치입니다.

**문제는, 지금 그 '재는 기능'이 제대로 작동하지 않는다는 점입니다.**

---

## 1부. 시급한 문제 4개

> 이 4개 때문에 **지금까지 저장된 기록은 믿을 수 없습니다.**
> 고치는 데는 반나절 정도면 됩니다. 다른 작업보다 먼저 하시길 권합니다.

### 문제 1 — 정답을 본 뒤에도 계속 답할 수 있어요

시험지를 내고 채점을 받았는데, **채점된 답안지에 답을 계속 더 쓸 수 있는** 상태입니다.

"🎉 정답! B 소리가 더 높았습니다" 메시지가 뜬 다음에도 '높음' 버튼이 여전히 눌립니다.
그리고 누를 때마다 **새 문제를 푼 걸로 집계됩니다.**

이미 정답을 알고 누르는 거니까 당연히 100% 맞습니다.
버튼을 몇 번 톡톡 두드리면 **정답률도, 최고 난이도 기록도 원하는 만큼 만들 수 있어요.**

> 영향받는 것: 시행 수, 정답 수, 정답률, 최소 음정 차이 — **통계 화면의 모든 숫자**

---

### 문제 2 — "다시 듣기"가 사실은 "새 문제"예요

소리를 놓쳐서 다시 듣기를 누르면, 사용자는 *방금 그 소리를 한 번 더* 듣는다고 생각하죠.

그런데 앱은 그 순간 **동전을 다시 던져서 정답을 새로 정합니다.**

방금 들은 게 "B가 높음"이었어도, 다시 듣기를 누르면 "B가 낮음"으로 바뀌어 있을 수 있습니다.
같은 소리를 다시 듣는 게 아니라 **완전히 다른 문제가 나오는 것**입니다.

게다가 어려운 문제가 나왔을 때 답하지 않고 다시 듣기만 계속 누르면
**마음에 안 드는 문제를 무한정 넘길 수 있습니다.** 그러면 쉬운 문제만 골라 푼 셈이 되죠.

---

### 문제 3 — 반응 시간이 항상 3초 넘게 나와요

통계 화면에 "평균 반응 시간"이 있습니다.
원래 이건 *소리를 다 듣고 나서 얼마나 빨리 판단했는가*를 재야 하는 숫자입니다.

그런데 지금은 **재생 버튼을 누른 순간부터** 시간을 잽니다.

```
[재생 버튼 누름] ──── 여기서부터 시간을 재기 시작 (X)
    소리 A     1.0초
    쉬는 시간  0.5초
    소리 B     1.0초
[답변 가능]    ──── 원래 여기서부터 재야 함 (O)
    사용자 판단
[답변]
```

소리 듣는 시간 2.5초가 무조건 포함되니까, **아무리 번개같이 답해도 3초 밑으로 나올 수 없습니다.**
지금 이 숫자는 사실상 아무 의미가 없습니다.

---

### 문제 4 — 소리가 1초가 아니라 사실상 0.3초예요

소리에는 원래 세 구간이 있어야 합니다.

```
정상:   ▁▄█████████▄▁     켜짐 → 유지 → 꺼짐
현재:   ▁█▇▆▅▄▃▂▁▁▁▁     켜지자마자 계속 사그라듦 ("유지"가 없음)
```

문서에는 "1초짜리 소리"라고 적혀 있지만, 실제로 귀에 들리는 건 **짧은 '삑' 소리**입니다.

이게 왜 중요하냐면 — **소리가 짧을수록 높낮이 구별이 훨씬 어렵습니다.**
즉 지금 사용자들은 **실제 실력보다 나쁘게 측정되고 있습니다.**

---

### 문제 4개 정리

| 문제 | 결과 |
|---|---|
| 답을 여러 번 낼 수 있음 | 점수를 마음대로 만들 수 있음 |
| 다시 듣기가 정답을 바꿈 | 어려운 문제를 회피할 수 있음 |
| 반응 시간에 재생 시간 포함 | 그 숫자가 의미 없음 |
| 소리가 사실상 짧음 | 실력이 실제보다 낮게 나옴 |

**→ 이 4개를 고치기 전까지 쌓이는 데이터는 분석에 쓰지 마세요.**

## 2부. 그다음으로 중요한 것

### 최고 기록이 운에 좌우됩니다

이 게임은 **찍어도 50% 확률로 맞습니다** (높음/낮음 둘 중 하나니까요).

지금 대표 지표인 "최소 음정 차이"는 *그 세션에서 도달한 가장 좋은 값 하나*입니다.
그런데 운 좋게 두 번 연속 찍어서 맞히면, 실력과 무관하게 이 값이 뚝 떨어집니다.
**한 번의 운이 기록으로 남는 구조**예요.

**해결:** 최고점 하나만 보지 말고, 난이도가 **오르내림을 반복하며 뒤집힌 지점들의 평균**을 내면
훨씬 안정적인 값이 나옵니다. 청각 실험에서 표준으로 쓰는 방식입니다.

비유하자면 — 체중을 잴 때 *일주일 중 가장 가벼웠던 순간*을 기록하는 대신
*아침저녁 오르내린 값의 평균*을 쓰는 것과 같습니다.

---

### "평가" 버튼이 아무 일도 안 합니다

훈련 화면 맨 위에 🏋️ 훈련 / 📋 평가 두 개 중 고르게 돼 있죠.

**코드상 이 둘은 완전히 똑같이 동작합니다.** 이름표만 다르게 저장될 뿐입니다.

특히 문제는, **평가할 때도 정답을 알려준다**는 점입니다.
정답을 알려주면 사용자가 도중에 요령을 배우게 되고,
그러면 "지금 이 사람의 실력은 얼마인가"라는 측정 목적이 무너집니다.

**평가 모드라면 이래야 합니다:**

| | 훈련 | 평가 |
|---|---|---|
| 문제마다 정답 알려주기 | ✅ 알려줌 | ❌ 끝날 때 한 번에 |
| 언제 끝나나 | 사용자 마음대로 | 정해진 문항 수 채우면 자동 종료 |
| 쉬운 함정 문제 섞기 | 없음 | 있음 (집중하고 있는지 확인용) |

---

### 첫 문제가 너무 어렵습니다

시작 난이도가 **50**인데, 이건 피아노 건반 한 칸의 절반입니다.

사용법 문서에도 이렇게 적혀 있어요:
> "차이가 크게 들리지 않는 것이 정상입니다"

정상이라고 안내하고는 있지만, 솔직히 이건 **처음 써 본 사람이 바로 포기할 만한 설정**입니다.
게다가 이 앱의 주 대상은 보청기·인공와우 사용자인데,
이분들은 훨씬 큰 차이부터 시작해야 하는 경우가 많습니다.

**해결:** 처음엔 누구나 맞힐 만큼 쉽게 시작 → 맞히면 성큼성큼 어렵게 →
자기 수준 근처에 오면 조금씩 미세하게 조정.

이러면 초보자는 첫 문제를 맞히며 기분 좋게 시작하고,
잘하는 사람도 대여섯 문제 만에 자기 수준에 도달합니다. 양쪽 다 이득이에요.

---

### 소리를 놓치는 상황이 처리되지 않습니다

- 소리 재생 중에 **전화가 오면** → 소리는 못 들었는데 답변 버튼은 활성화됨
- **앱을 잠깐 나갔다 오면** → 마찬가지
- **이어폰을 뽑으면** → 마찬가지

이 경우 사용자는 찍을 수밖에 없고, 그 찍은 답이 기록에 그대로 남습니다.

## 3부. 디자인

### 이모지를 아이콘으로 쓰고 있어요

🎵 🎧 📊 ⚙️ 🏋️ 📋 🌊 🎤 🔥 🏆 🎯 ⏱️ 🗑️ ⬆️ ⬇️ — 앱 전체에 이모지가 아이콘 역할을 합니다.

문제점:
- **폰마다 모양이 다르게 보입니다** (삼성/구글/LG가 다 다름)
- **색을 맞출 수 없습니다** (앱 색상 테마와 따로 놉니다)
- **크기·정렬이 어긋납니다**
- **화면 읽어주는 기능이 "불 이모지"라고 읽습니다**

그런데 **제대로 된 아이콘 세트가 이미 설치돼 있는데 하나도 안 쓰고 있습니다.**
바꾸는 데 추가 설치도 필요 없습니다.

---

### 가장 중요한 문구가 가장 안 보입니다

홈 화면 맨 아래 **"본 앱은 의료기기가 아닙니다..."** 라는 법적 고지문이 있죠.

이게 하필 **앱에서 가장 흐린 회색 + 가장 작은 글씨(11px)** 로 되어 있습니다.
배경과의 밝기 차이를 계산해 보니 접근성 기준(4.5 대 1)에 못 미칩니다(약 3.9 대 1).

법적으로 중요한 문구일수록 잘 보여야 합니다.

---

### 막대 그래프가 A와 B를 구분 못 합니다

화면 가운데 막대 그래프가 두 묶음 있죠. 왼쪽이 A, 오른쪽이 B입니다.

그런데 **A 소리가 날 때 B 쪽 막대도 똑같이 흔들립니다.** 색만 회색일 뿐이에요.
"지금 어느 소리가 나고 있는지"를 보여주는 게 이 그래프의 존재 이유인데, 그 역할을 못 하고 있습니다.

그리고 B 소리의 주파수가 **답을 맞힌 뒤에도 계속 `? Hz`** 로 남아 있습니다.
정답 공개 후에는 "452 Hz (기준보다 +50)"처럼 실제 값을 보여주면 학습에 도움이 됩니다.

---

### 훈련 화면에 정보가 너무 많습니다

위에서부터 순서대로:

```
뒤로 · 제목
훈련 / 평가          ← 세션 중엔 못 바꾸는데 계속 자리 차지
순수 파형 / 목소리    ← 위와 동일
음정차이 · 기준Hz · 연속   (배지 3개)
시행 n회 · 정답률 n%
[ 막대 그래프 180px ]
▶️ 소리 듣기          ← 정작 제일 중요한 버튼이 여기
질문 문구
[높음] [낮음]         ← 두 번째로 중요한 버튼
피드백 카드
세션 종료
```

작은 폰에서는 **가장 많이 누르는 버튼이 스크롤을 내려야 나옵니다.**

**해결 방향:** 시작 전에 고르는 것들(훈련/평가, 소리 종류)은 **시작 화면으로 분리**하고,
훈련 중 화면은 [진행 상황 → 그래프 → 버튼] 세 덩어리로 단순하게.

---

### 손가락으로 누르기 작은 버튼들

안드로이드 권장 최소 크기는 48dp인데:

- 훈련/평가 버튼: 약 34
- 뒤로 가기 버튼: 약 26

특히 뒤로 가기는 절반 크기입니다. 고령 사용자나 손 떨림이 있는 분에게는 꽤 불편합니다.

---

### 화면마다 스타일이 조금씩 다릅니다

- 제목 글자 크기: 훈련 화면 20px, 통계·설정 화면 15px
- 훈련 화면 상단에만 밑줄이 없음
- 흰색을 뜻하는 이름이 두 개(`text`, `textPrimary`)라 화면마다 다른 걸 씀

**같은 역할인데 화면마다 다르게 생긴 상태**입니다.
공용 부품(제목 바, 카드, 버튼)을 하나로 만들어 쓰면 자동으로 통일되고, 코드도 700줄쯤 줄어듭니다.

## 4부. 있으면 좋을 기능

### 처음 쓰는 사람을 위한 안내 (효과 가장 큼)

지금은 홈에서 바로 훈련으로 들어갑니다. 그래서 **볼륨이 작아서 못 듣는 건지, 실력인지 구분이 안 됩니다.**
(사용법 FAQ에도 "소리가 안 들려요" 항목이 있죠.)

첫 실행 때 3단계만 있으면 좋겠습니다:
1. **이어폰 쓰세요** 안내
2. **볼륨 맞추기** — 기준음을 계속 들려주면서 "편하게 들리는 크기로 맞춰주세요"
3. **연습 3문제** — 아주 쉬운 차이로, 점수에는 반영 안 함

---

### 세션 끝나면 뜨는 팝업 → 결과 화면으로

지금은 훈련이 끝나면 **작은 시스템 팝업**이 뜨고 끝입니다.
```
시행 5회
정답률 60%
최소 음정 차이 40
```

이걸 제대로 된 결과 화면으로 만들면 좋겠습니다:
- 이번 기록 + **지난번보다 얼마나 좋아졌는지** (↓12 개선!)
- 문제를 풀면서 난이도가 어떻게 오르내렸는지 작은 그래프
- "한 판 더" / "홈으로" 버튼

---

### 성장 그래프

통계 화면에 **숫자 타일 4개와 목록**만 있습니다.

이런 훈련 앱에서 사람을 계속 오게 만드는 건 **"내가 늘고 있다"는 시각적 증거**입니다.
날짜별 기록 선그래프 하나만 있어도 체감이 완전히 달라집니다.
그림 그리는 도구는 이미 설치돼 있어서 추가 설치도 필요 없습니다.

---

### 기록 내보내기

지금 모든 기록은 **폰 안에만** 있습니다.
**앱을 지우면 전부 사라지고, 백업할 방법도 없습니다.**

파일로 내보내기(공유) 기능이 있으면:
- 기기를 바꿔도 기록이 남고
- 병원이나 상담사에게 보여줄 수 있습니다

---

### 진동 피드백

정답/오답일 때 짧게 **진동**을 주면 좋겠습니다.
청각 보조 기기를 쓰는 분들에게는 특히 도움이 됩니다.

이 기능도 **이미 설치는 돼 있는데 안 쓰고 있습니다.**

---

### 세션 목표

지금은 "언제까지 해야 하는지" 알 수 없이 계속 문제가 나옵니다.
"오늘 20문제" 같은 목표와 진행 바가 있으면 끝맺음이 명확해집니다.

참고로 지금 화면 아래 `0/3` 표시는 **"기록을 저장하려면 3문제는 풀어야 한다"**는 뜻인데,
사용자에게는 오늘의 목표처럼 보입니다. 문구를 명확히 하는 게 좋겠습니다.

특히 **패키지 이름은 변경 불가**입니다. 출시 전에 반드시 정리해야 합니다.

### ⚠️ 앱 이름이 "청능 애플리케이션"입니다

이건 좀 신경 쓰이는 부분입니다.

명세서에 **쓰면 안 되는 용어 목록**을 따로 만들어 두셨죠 —
청력 검사, 청력 진단, 청각 재활, 치료 같은 병원 용어들이요.
앱 안에서도 "의료기기가 아닙니다", "음고 인지 감각 훈련"이라고 조심스럽게 쓰고 계십니다.

**그런데 스토어에 뜨는 앱 이름만 병원 용어입니다.**
"청능(聽能)"은 청능재활을 바로 연상시키는 임상 용어예요.

사용자가 스토어에서 보는 첫 화면이 앱 이름인데, 여기서 앞뒤가 안 맞으면
그동안 조심하신 게 의미가 없어집니다. **"하모니튠"으로 통일**하시길 권합니다.

## 6부. 정리 안 된 것들 (개발 쪽)

기술적인 이야기라 짧게만 적습니다. 자세한 건 원본 문서를 봐주세요.

- **안 쓰는 라이브러리가 6개** 설치돼 있습니다. 특히 `rive-react-native`는 무거운 데다
  전혀 호출되지 않습니다 — 안드로이드 빌드가 실패했던 이력이 있는 프로젝트라 특히 정리를 권합니다.
- **테스트가 0개**입니다. 테스트 도구는 설정돼 있는데 파일이 하나도 없어요.
  위에서 고칠 문제들이 다시 재발하지 않게 하려면 테스트를 함께 넣어야 합니다.
- **기록이 쌓일수록 느려집니다.** 저장할 때마다 지금까지의 모든 기록을 통째로 읽고 다시 쓰는 구조라,
  세션이 수백 개 쌓이면 문제가 됩니다.
- **저장 실패해도 "완료"라고 뜹니다.** 실제로는 저장이 안 됐는데 성공 메시지가 나옵니다.
- **화면 하나가 560줄**입니다. 소리 재생, 채점, 화면 그리기가 한 파일에 다 있어서
  고치기 어렵고 테스트도 안 됩니다.
- **"사람 목소리" 실제 녹음 기능**의 계산 코드는 다 짜여 있는데 **어디서도 쓰이지 않습니다.**
  녹음 파일이 없어서 연결을 못 한 상태예요.
